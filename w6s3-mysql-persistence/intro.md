## 클라우드인프라관리 6주차 3차시 실습 (6주차 마지막 시간)

지난 시간에 PV와 PVC를 만들어봤습니다. 오늘은 그걸 실제로 써먹어 볼 차례입니다. 진짜
데이터베이스인 MySQL을 K8s에 배포하고, Pod를 강제로 삭제했다가 다시 살아나도 데이터가 그대로인지
직접 눈으로 확인해봅니다.

**이번 실습이 시작되기 전에**: 지난 2차시에서 만든 `mysql-pv`, `mysql-pvc`를 지우지 않았는지
확인하세요. 만약 삭제했다면 2차시의 pv.yaml/pvc.yaml을 다시 `kubectl apply`하면 됩니다.

검증 절차는 세 단계입니다.
1. MySQL Pod에 접속해서 테이블을 하나 만들고 데이터를 한 줄 넣습니다.
2. `kubectl delete pod`로 그 Pod를 강제로 삭제합니다. Deployment이므로 자동으로 새 Pod가
   만들어집니다.
3. 새로 생성된 Pod에 접속해서 아까 넣은 데이터가 SELECT로 그대로 조회되는지 확인합니다.

만약 PVC 없이 그냥 MySQL을 배포했다면, Pod가 삭제되고 새로 생기는 순간 데이터가 전부 사라졌을
것입니다. 오늘 우리는 PVC 덕분에 데이터가 살아남는 것을 직접 확인합니다.

**타이밍 주의**: Pod 삭제 후 새 Pod가 완전히 Running 상태가 되기까지 **10~20초 정도** 걸립니다.
조급해하지 말고 `kubectl get pods`로 상태를 확인하면서 기다려주세요.
