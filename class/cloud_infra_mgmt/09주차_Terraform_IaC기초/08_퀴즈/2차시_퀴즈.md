# 9주차 2차시 — Terraform 설치와 HCL 문법 퀴즈 (OX·단답형 8문항)

- 범위: 9주차 2차시(Terraform 설치, HCL 문법, init/plan/apply)
- 형식: OX 5문항 + 단답형 3문항
- 용도: LMS 자동채점 퀴즈. 수업 중 함께 풀고 바로 정답·해설을 확인합니다.

---

## OX 문제 (1~5번)

**1.** Terraform은 HashiCorp가 제공하는 공식 apt 저장소를 통해 설치할 수 있다. ( )

**2.** HCL 코드에서 provider 블록은 실제로 만들고 싶은 대상(리소스)을 선언하는 블록이다. ( )

**3.** `resource "docker_container" "web"`에서 `"web"`은 Terraform 코드 안에서 이 리소스를 부르는
이름이며, 실제로 생성되는 컨테이너 이름과 다를 수 있다. ( )

**4.** `terraform apply -auto-approve`를 실행하면 "진행할까요?"라는 확인 질문 없이 바로 인프라가
생성된다. ( )

**5.** `terraform init`은 코드에 필요한 Provider를 다운로드하고 작업 폴더를 초기화하는 명령이다.
( )

## 단답형 문제 (6~8번)

**6.** HCL 코드에서 "어떤 인프라(Docker 등)를 다룰지"를 선언하는 블록의 이름은 무엇인가요?

**7.** `resource "docker_container" "web" { name = "tf-nginx" ... }`처럼 작성했을 때, 실제로 Docker에
생성되는 컨테이너의 이름은 무엇인가요?

**8.** `terraform plan`과 `terraform apply`의 차이를 한 문장으로 설명하세요.

---

## 정답 및 해설

| 번호 | 정답 | 해설 |
|---|---|---|
| 1 | O | Terraform은 HashiCorp 공식 apt 저장소에서 GPG 키 등록 후 `apt-get install`로 설치한다. |
| 2 | X | 반대다. provider 블록은 "어떤 인프라를 다룰지"를 선언하고, 실제로 만들고 싶은 대상은 resource 블록이 선언한다. |
| 3 | O | `"web"`은 Terraform 코드 안에서의 식별자이고, `name = "tf-nginx"`가 실제 Docker에 생성되는 컨테이너 이름이다. 코드 안의 이름과 실제 인프라의 이름은 별개다. |
| 4 | O | `-auto-approve`는 apply 전에 나오는 확인 질문을 건너뛰는 옵션이다. |
| 5 | O | init은 main.tf에 선언된 Provider(예: docker)를 다운로드하고 작업 폴더를 초기화한다. |
| 6 | provider | provider 블록은 어떤 인프라를 다룰지(예: `provider "docker" {}`)를 선언한다. |
| 7 | tf-nginx | `name` 속성에 지정한 값이 실제로 생성되는 컨테이너 이름이다. |
| 8 | (예시) plan은 무엇이 바뀔지 미리 보여주기만 하고 아직 실제로 적용하지 않으며, apply는 plan에서 본 내용을 실제로 실행해서 인프라를 생성·변경한다. | 핵심은 "미리보기(plan)"와 "실제 실행(apply)"의 차이 — 채점 시 이 취지가 담기면 정답 처리 |
