# 9주차 1차시 — IaC 개념과 Terraform 아키텍처 퀴즈 (OX·단답형 8문항)

- 범위: 9주차 1차시(IaC 개념, Terraform 아키텍처)
- 형식: OX 5문항 + 단답형 3문항
- 용도: LMS 자동채점 퀴즈. 수업 중 함께 풀고 바로 정답·해설을 확인합니다.

---

## OX 문제 (1~5번)

**1.** IaC(Infrastructure as Code)는 인프라를 코드로 선언하고, 그 코드를 실행해서 생성·변경·삭제하는
방식이다. ( )

**2.** 서버가 10대, 100대로 늘어날수록 매번 손으로 명령어를 반복 입력하는 것이 IaC보다 효율적이다.
( )

**3.** Provider는 Terraform과 각 인프라(Docker, AWS, GCP 등) 사이를 연결해주는 플러그인이다. ( )

**4.** `terraform plan`은 코드를 실제로 실행해서 인프라를 생성·변경하는 명령이다. ( )

**5.** 이번 학기에는 9주차에 docker Provider, 10주차에 Terraform Cloud와 random Provider를 사용한다.
( )

## 단답형 문제 (6~8번)

**6.** Terraform 코드를 실행하면 무엇이 바뀔지 실제로 적용하기 전에 미리 보여주는(견적서 역할)
명령어는 무엇인가요?

**7.** HCL 코드가 어떤 인프라(Docker, AWS 등)의 API를 호출할지 연결해주는, Terraform의 플러그인
개념을 무엇이라고 부르나요?

**8.** IaC가 주는 이점 네 가지(재현성·버전 관리·자동화·문서화) 중, "코드 자체가 지금 인프라가 어떻게
구성되어 있는지 보여주는 살아있는 기록이 된다"에 해당하는 이점은 무엇인가요?

---

## 정답 및 해설

| 번호 | 정답 | 해설 |
|---|---|---|
| 1 | O | IaC는 인프라를 코드로 선언하고, 그 코드로 생성·변경·삭제하는 방식이다. |
| 2 | X | 서버 대수가 많아질수록 손으로 반복 입력하면 실수·누락이 생기기 쉽다. 이런 문제를 해결하는 것이 IaC다. |
| 3 | O | Provider는 Terraform과 각 인프라 사이를 연결해주는 플러그인이며, 어떤 Provider를 쓰느냐에 따라 Docker 컨테이너를 만들 수도, AWS 서버를 만들 수도 있다. |
| 4 | X | `plan`은 무엇이 바뀔지 미리 보여줄 뿐 아직 실제로 적용하지 않는다. 실제로 실행하는 것은 `apply`다. |
| 5 | O | 9주차는 docker Provider로 로컬 실습, 10주차는 Terraform Cloud와 random Provider로 원격 실행·State 관리를 배운다. |
| 6 | `terraform plan` | plan은 "이렇게 바뀔 예정입니다"라는 견적서 역할을 하며, apply 전에 변경 사항을 미리 확인시켜준다. |
| 7 | Provider | Provider는 HCL 문법과 실제 인프라(Docker, AWS 등) API 사이를 연결해주는 플러그인이다. |
| 8 | 문서화 | 코드 자체가 인프라 구성을 보여주는 기록이 되는 것이 문서화의 이점이다. |
