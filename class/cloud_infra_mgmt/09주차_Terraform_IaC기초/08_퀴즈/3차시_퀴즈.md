# 9주차 3차시 — destroy와 State 파일 퀴즈 (OX·단답형 8문항)

- 범위: 9주차 3차시(terraform destroy, State 파일, 로컬 State의 한계)
- 형식: OX 5문항 + 단답형 3문항
- 용도: LMS 자동채점 퀴즈. 수업 중 함께 풀고 바로 정답·해설을 확인합니다.

---

## OX 문제 (1~5번)

**1.** `terraform destroy`는 코드에 선언된 리소스가 여러 개일 경우, 하나씩 개별적으로 지워야 한다.
( )

**2.** `terraform apply`를 실행하면 `terraform.tfstate`라는 파일이 자동으로 생성된다. ( )

**3.** State 파일은 사람이 직접 손으로 수정해도 안전하다. ( )

**4.** 로컬(내 VM)에만 저장된 State 파일에는 비밀번호 같은 민감한 정보가 평문으로 포함될 수 있어
보안 위험이 있다. ( )

**5.** Terraform은 State, 실제 인프라, 코드 세 가지를 비교해서 차이(diff)만 반영한다. ( )

## 단답형 문제 (6~8번)

**6.** `terraform apply`를 실행할 때마다 자동으로 생성되며, "지금 무엇을 만들었는지"를 기록하는
파일의 이름은 무엇인가요?

**7.** 여러 사람이 각자 로컬 State 파일을 따로 가지고 같이 작업할 때 발생할 수 있는 문제를 한
단어(또는 짧은 구)로 쓰세요.

**8.** State 파일의 내용을 직접 열람할 때 쓸 수 있는 명령을 `cat terraform.tfstate` 외에 한 가지 더
쓰세요.

---

## 정답 및 해설

| 번호 | 정답 | 해설 |
|---|---|---|
| 1 | X | `terraform destroy` 한 번이면 코드에 선언된 리소스를 전부 제거한다. 여러 개를 만들었어도 하나하나 지울 필요가 없다. |
| 2 | O | `terraform apply`를 실행하면 `terraform.tfstate` 파일이 자동으로 생성되어 현재 인프라 상태를 기록한다. |
| 3 | X | State 파일을 사람이 직접 손으로 수정하는 것은 매우 위험하다. 반드시 `terraform` 명령을 통해서만 다뤄야 한다. |
| 4 | O | 로컬 State 파일에는 민감한 정보가 평문으로 포함될 수 있어 보안 위험이 있다. 이 문제를 해결하는 것이 다음 주에 배울 원격 State다. |
| 5 | O | State, 실제 인프라, 코드를 비교해서 차이만 반영하는 것이 Terraform의 핵심 동작 원리다. |
| 6 | terraform.tfstate | apply 실행 시 자동 생성되며, 리소스의 ID·속성값 등 현재 상태가 기록된다. |
| 7 | (State) 충돌 | 여러 사람이 각자 다른 State 정보를 가지면 서로 충돌이 날 수 있다. |
| 8 | terraform show | `cat terraform.tfstate` 또는 `terraform show`로 State 파일 내용을 확인할 수 있다. |
