# 9주차 1차시 실습가이드

## 개요

오늘은 IaC(Infrastructure as Code) 개념과 Terraform의 기본 아키텍처(HCL, Provider)를 배우는
시간입니다. 아직 VM에 Terraform을 설치하지 않으므로 새로 실행할 실습 코드는 없지만, 9주차부터
14주차까지 VM에 Terraform·Jenkins 등 새 도구를 계속 설치해야 하므로, 이번 시간에는 **1~7주차 실습에
쓰던 컨테이너와 minikube를 정리**해서 VM 여유 공간을 확보합니다. 소요 시간은 약 10분입니다.

## VM 실습

VM 스펙은 기본 2 vCPU·RAM 4GB로 넉넉하지 않습니다. 1~7주차 실습은 이미 끝났고 과제 제출도
완료했을 것이므로, 아래 순서대로 정리해도 안전합니다.

### 1) 정리 전 디스크 여유 공간 확인

```bash
df -h
```

출력에서 `/` 파티션의 `Avail`(사용 가능 용량) 칸의 값을 기억해두세요. 정리를 마친 뒤 이 값과
비교해서 얼마나 여유 공간이 늘었는지 확인할 것입니다.

### 2) 지금 떠 있는 컨테이너 확인

```bash
docker ps -a
```

`STATUS` 칸이 `Up ...`(실행 중)이든 `Exited ...`(종료됨)든 상관없이, 1~7주차에 실습하며 만든
컨테이너(nginx, mysql 등)가 목록에 나타납니다.

### 3) 실행 중인 컨테이너 전부 정지

```bash
docker stop $(docker ps -aq)
```

`docker ps -aq`는 모든 컨테이너의 ID만 뽑아내고, 그 목록을 `docker stop`에 그대로 넘겨서 한 번에
정지시킵니다. 이미 정지된 컨테이너가 포함되어도 오류처럼 보이는 메시지가 나올 수 있지만
걱정하지 않아도 됩니다.

### 4) 정지된 컨테이너 전부 삭제

```bash
docker rm $(docker ps -aq)
```

컨테이너 자체를 삭제합니다. 컨테이너 안에 저장했던 데이터(볼륨을 쓰지 않은 경우)는 이 시점에
함께 사라지는데, 1~7주차 실습은 이미 끝났고 제출도 완료했을 것이므로 안전합니다.

### 5) 안 쓰는 이미지·네트워크·볼륨까지 한 번에 정리

```bash
docker system prune -a --volumes
```

`-a`는 실행 중이지 않은 모든 이미지까지, `--volumes`는 어디에도 연결되지 않은 볼륨까지 포함해서
정리합니다. 확인 메시지(`y/N`)가 뜨면 `y`를 입력하세요. 이렇게 지운 이미지는 나중에 다시
필요해지면 `docker run`이나 `docker build` 시 자동으로 재다운로드되니 걱정하지 않아도 됩니다.

### 6) minikube가 켜져 있다면 정지

```bash
minikube status
minikube stop
```

`minikube status`의 출력이 `Running`이라면 `minikube stop`으로 꺼두세요. 9~14주차는 minikube를
쓰지 않으므로 계속 띄워둘 필요가 없습니다. (나중에 다시 필요하면 `minikube start`로 다시 켜면
됩니다.)

### 7) 정리 후 디스크 여유 공간 다시 확인

```bash
df -h
```

1)번에서 확인했던 `Avail` 값과 비교해서 여유 공간이 늘어난 것을 확인하세요.

## 제출 안내

이번 차시는 VM 실습 결과물을 별도로 제출하지 않습니다. 위 정리 과정을 이번 주 안에 완료했는지만
스스로 확인하면 됩니다.

다음 2차시부터는 개인 VM에 Terraform을 직접 설치하고, HCL 문법을 배워 실제 Docker 컨테이너를
코드로 배포합니다.
