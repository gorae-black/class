# 9주차 2차시 실습가이드

## 개요

오늘은 개인 VM에 Terraform을 직접 설치하고, HCL(HashiCorp Configuration Language)의 핵심 문법인
provider·resource 블록을 배워서 실제 Docker 컨테이너를 코드로 배포합니다. 소요 시간은 약 20분입니다.

## VM 실습

### 1) Terraform 설치

HashiCorp가 공식으로 제공하는 apt 저장소를 통해 설치합니다. 아래 명령어를 순서대로 입력하세요.

```bash
wget -O- https://apt.releases.hashicorp.com/gpg | \
  sudo gpg --dearmor -o /usr/share/keyrings/hashicorp-archive-keyring.gpg
echo "deb [signed-by=/usr/share/keyrings/hashicorp-archive-keyring.gpg] https://apt.releases.hashicorp.com $(lsb_release -cs) main" | \
  sudo tee /etc/apt/sources.list.d/hashicorp.list
sudo apt-get update && sudo apt-get install -y terraform
```

> 참고: 첫 번째 명령은 HashiCorp의 공식 GPG 키를 등록하고, 두 번째 명령은 apt 저장소 목록에
> HashiCorp 저장소를 추가합니다. 세 번째 명령이 패키지 목록을 갱신하고 Terraform을 설치합니다.

설치가 끝나면 버전을 확인해서 정상 설치됐는지 검증합니다.

```bash
terraform -version
```

### 2) 작업 폴더와 main.tf 작성

작업할 폴더를 만들고 이동한 뒤, `main.tf` 파일을 작성합니다.

```bash
mkdir -p ~/terraform-lab && cd ~/terraform-lab
```

`main.tf` 파일에 아래 내용을 작성합니다. (에디터는 `nano main.tf` 또는 `vi main.tf` 등 편한 것을
사용하세요.)

```hcl
provider "docker" {}

resource "docker_container" "web" {
  name  = "tf-nginx"
  image = "nginx:latest"
  ports {
    internal = 80
    external = 8080
  }
}
```

코드를 하나씩 살펴보면 다음과 같습니다.

- `provider "docker" {}` — Docker를 다루겠다고 선언하는 블록입니다.
- `resource "docker_container" "web"` — `docker_container`가 리소스 타입, `web`은 이 리소스를
  Terraform 코드 안에서 부르는 이름입니다(실제 컨테이너 이름과는 별개입니다).
- `name = "tf-nginx"` — 실제로 생성될 컨테이너의 이름입니다.
- `image = "nginx:latest"` — 사용할 이미지입니다(3주차 `docker run`에서 쓰던 이미지 이름과 같은
  개념입니다).
- `ports { internal = 80; external = 8080 }` — 컨테이너 내부 80번 포트를 호스트의 8080번 포트로
  매핑합니다.

### 3) init — Provider 다운로드

```bash
terraform init
```

`main.tf`에 `docker` Provider가 필요하다고 선언되어 있으므로, 이 단계에서 해당 Provider를
다운로드하고 작업 폴더를 초기화합니다. `Terraform has been successfully initialized!` 메시지가
나오면 성공입니다.

### 4) plan — 변경 사항 미리보기

```bash
terraform plan
```

`docker_container.web`을 새로 만들 예정이라는 견적을 보여줍니다. 이 단계에서는 아직 실제로 아무것도
생성되지 않습니다.

### 5) apply — 실제 생성

```bash
terraform apply -auto-approve
```

plan에서 본 내용을 실제로 실행해서 컨테이너를 생성합니다. `-auto-approve`는 "진행할까요?"라는 확인
질문을 건너뛰는 옵션입니다.

### 6) 결과 확인

```bash
docker ps
```

`tf-nginx`라는 이름의 컨테이너가 떠 있는지 확인합니다.

## 제출 안내

`docker ps` 실행 결과에 `tf-nginx` 컨테이너가 정상적으로 떠 있는 화면을 캡처해서 제출하세요.

**주의:** 오늘 만든 `tf-nginx` 컨테이너를 지우지 마세요. 다음 3차시에 이 컨테이너를
`terraform destroy`로 지우고 State 파일을 확인하는 실습을 이어서 진행합니다.
