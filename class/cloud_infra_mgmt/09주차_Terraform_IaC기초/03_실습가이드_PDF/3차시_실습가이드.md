# 9주차 3차시 실습가이드

## 개요

오늘은 지난 2차시에 만든 `tf-nginx` 컨테이너를 `terraform destroy`로 제거하고, Terraform이 "지금
무엇을 만들었는지"를 어떻게 기억하는지(State 파일)를 확인합니다. 9주차의 마지막 차시이므로,
1~3차시 실습 결과를 종합해서 제출합니다. 소요 시간은 약 15분입니다.

## VM 실습

2차시에 작업했던 폴더로 이동합니다.

```bash
cd ~/terraform-lab
```

### 1) destroy 전 State 파일 내용 확인

컨테이너를 지우기 **전에**, 먼저 State 파일에 어떤 정보가 기록되어 있는지 직접 열람합니다.

```bash
cat terraform.tfstate
```

또는

```bash
terraform show
```

`docker_container.web`(실제 컨테이너 이름 `tf-nginx`)에 대한 리소스 ID, 속성값 등이 기록되어
있는 것을 확인하세요.

### 2) terraform destroy 실행

```bash
terraform destroy -auto-approve
```

`main.tf`에 선언된 리소스(`docker_container.web`)를 제거합니다. `-auto-approve`를 붙이지 않으면
"무엇을 지울 예정인지" 먼저 보여주고 확인(`yes` 입력)을 거칩니다. 여러 리소스를 선언했더라도
`terraform destroy` 한 번으로 전부 제거됩니다.

### 3) 컨테이너가 사라졌는지 확인

```bash
docker ps
```

`tf-nginx` 컨테이너가 목록에서 사라진 것을 확인합니다.

### 4) destroy 후 State 파일 다시 확인

```bash
cat terraform.tfstate
```

또는

```bash
terraform show
```

destroy 전과 비교해서, `docker_container.web`에 대한 리소스 기록이 사라졌는지 확인합니다.

## 제출 안내

이번 차시는 9주차의 마지막 시간입니다. 아래 두 가지를 캡처하고, **1차시(개념)·2차시(설치·배포)·
3차시(오늘, destroy·State) 실습 결과를 종합**해서 LMS 과제 게시판에 제출하세요.

1. `docker ps` 실행 결과 — `tf-nginx` 컨테이너가 사라진 화면
2. `cat terraform.tfstate`(또는 `terraform show`) 실행 결과 — 리소스 기록이 사라진 화면

다음 10주차에서는 오늘 다룬 로컬 State의 한계(협업 시 충돌, 민감정보 평문 노출)를 해결하는
Terraform Cloud와 원격 State 관리를 배웁니다. 10주차부터 Terraform Cloud 계정 가입이 필요하며,
가입 가이드는 10주차 2차시에 단계별로 안내될 예정입니다.
