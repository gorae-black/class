# 5주차 3차시 — Endpoints와 라운드로빈 퀴즈 (OX·단답형 6문항)

- 범위: 5주차 3차시(Endpoints, 라운드로빈 부하분산)
- 형식: OX 4문항 + 단답형 2문항
- 용도: LMS 자동채점 퀴즈. 수업 중 함께 풀고 바로 정답·해설을 확인합니다.

---

## OX 문제 (1~4번)

**1.** Endpoints는 Service 뒤에 실제로 연결된 Pod들의 IP 목록을 보여주는 오브젝트이다. ( )

**2.** Pod가 새로 추가되거나 삭제되어도 Endpoints 목록은 수동으로 갱신해줘야 한다. ( )

**3.** Service로 여러 번 요청이 들어오면, 뒤에 있는 Pod들에게 순서대로 돌아가며(라운드로빈) 전달된다.
( )

**4.** 오늘 실습에서 쓴 nginx 기본 페이지는 어느 Pod가 응답했는지 curl 응답 내용만으로 쉽게 구분할
수 있다. ( )

## 단답형 문제 (5~6번)

**5.** `kubectl get endpoints myapp`을 실행했을 때 확인할 수 있는 정보는 무엇인가요?

**6.** 오늘 실습에서 반복 curl 요청이 실제로 어느 Pod로 분산되어 처리됐는지 확인하기 위해 사용한
명령어는 무엇인가요?

---

## 정답 및 해설

| 번호 | 정답 | 해설 |
|---|---|---|
| 1 | O | Endpoints는 Service의 '연결 장부'로, 그 시점에 실제로 연결된 Pod IP 목록을 그대로 보여준다. |
| 2 | X | Pod가 추가되거나 삭제될 때마다 Endpoints 목록은 **자동으로** 갱신된다. |
| 3 | O | 요청이 여러 번 들어오면 뒤에 있는 Pod들에게 순서대로 돌아가며 전달되는데, 이를 라운드로빈이라 한다. |
| 4 | X | nginx 기본 페이지는 어느 Pod가 응답하든 내용이 똑같아서, curl 결과만으로는 어느 Pod가 응답했는지 구분하기 어렵다. `kubectl logs`로 각 Pod의 로그를 확인해야 한다. |
| 5 | (예시) Service(myapp)에 실제로 연결되어 있는 Pod들의 IP(및 포트) 목록 | `ENDPOINTS` 칸에 Pod IP가 콤마로 구분되어 나열된다. |
| 6 | `kubectl logs {파드 이름}` | 각 Pod의 로그를 확인해, 반복 요청이 두 Pod에 나뉘어 기록되는지 비교했다. |
