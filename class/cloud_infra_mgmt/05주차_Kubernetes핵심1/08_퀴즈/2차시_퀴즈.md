# 5주차 2차시 — Service 타입과 NodePort 퀴즈 (OX·단답형 6문항)

- 범위: 5주차 2차시(Service 세 가지 타입 비교, NodePort 실습)
- 형식: OX 4문항 + 단답형 2문항
- 용도: LMS 자동채점 퀴즈. 수업 중 함께 풀고 바로 정답·해설을 확인합니다.

---

## OX 문제 (1~4번)

**1.** ClusterIP 타입 Service는 클러스터 외부에서도 자유롭게 접속할 수 있다. ( )

**2.** LoadBalancer 타입은 AWS, GCP 같은 클라우드 사업자가 제공하는 실제 로드밸런서를 통해 접속하는
방식으로, 운영 환경에서 주로 사용된다. ( )

**3.** 우리 실습에서 NodePort를 쓰는 이유는 로컬 minikube 환경에 실제 로드밸런서가 없기 때문이다.
( )

**4.** `kubectl expose deployment myapp --type=NodePort --port=80` 명령의 `--port=80`은 외부에서
접속할 때 사용할 NodePort 번호를 직접 지정하는 옵션이다. ( )

## 단답형 문제 (5~6번)

**5.** `kubectl get svc myapp`으로 확인한 `PORT(S)` 칸이 `80:31234/TCP`로 나왔을 때, 외부 접속에
실제로 사용해야 할 포트 번호는 몇 번인가요?

**6.** minikube 환경에서 NodePort Service의 접속 가능한 전체 URL을 바로 확인할 수 있는 명령어를
쓰세요.

---

## 정답 및 해설

| 번호 | 정답 | 해설 |
|---|---|---|
| 1 | X | ClusterIP는 클러스터 **내부**에서만 접속 가능한 기본 타입이다. 외부 접속에는 NodePort나 LoadBalancer를 쓴다. |
| 2 | O | LoadBalancer는 클라우드 사업자가 제공하는 진짜 로드밸런서를 통해 접속하며, 운영 환경에서 실제 서비스를 외부에 공개할 때 사용한다. |
| 3 | O | minikube 같은 로컬 환경에는 AWS·GCP 같은 로드밸런서가 없으므로, 로컬에서도 외부 접속을 흉내낼 수 있는 NodePort를 실습용으로 사용한다. |
| 4 | X | `--port=80`은 **Service가 받을 포트**(ClusterIP 포트)를 뜻한다. 실제 NodePort 번호는 30000~32767 범위에서 자동 할당된다. |
| 5 | 31234 | `80:31234/TCP`에서 뒤쪽 숫자(31234)가 외부에서 접속할 때 쓰는 NodePort 번호다. |
| 6 | `minikube service {서비스이름} --url` (예: `minikube service myapp --url`) | minikube가 접속 가능한 전체 URL을 바로 알려준다. |
