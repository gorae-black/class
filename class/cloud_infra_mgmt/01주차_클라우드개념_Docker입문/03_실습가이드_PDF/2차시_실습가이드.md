# 1주차 2차시 실습가이드

## 개요

지금까지 개념으로만 배운 컨테이너를 직접 실행해 볼 시간입니다. 이 터미널도, 0주차에 만든 개인
로컬 VM도 사실은 같은 원리(격리된 리눅스 환경)로 동작합니다. 소요시간은 Killercoda 15분 + VM
안내 5분입니다.

## Part A. Killercoda 실습

LMS > 1주차 > 2차시 > `05_Killercoda_링크`의 URL로 접속한 뒤 아래 순서대로 진행하세요.

> 이 세션은 **60분 제한**이 있습니다. 실습 중 시간이 종료되어도 당황하지 마세요 — 오늘 실습은
> 짧게 끝나므로 문제 없지만, 만약 중간에 끊기면 LMS의 링크로 다시 접속해 이어서 진행하면 됩니다.

**[1] 첫 번째 컨테이너 실행하기**

`docker run`은 "이미지를 실행해서 컨테이너로 만들어라"는 명령어입니다. `hello-world` 이미지가
로컬에 없으면 Docker Hub에서 자동으로 내려받은(pull) 뒤 실행합니다.

```
docker run hello-world
```

실행 결과 예시:

```
Unable to find image 'hello-world:latest' locally
latest: Pulling from library/hello-world
...
Hello from Docker!
This message shows that your installation appears to be working correctly.
```

"Hello from Docker!" 메시지가 보이면 성공입니다.

**[2] 이미지 목록 확인하기**

`docker images`는 현재 로컬에 저장된 이미지 목록을 보여줍니다. 이미지는 컨테이너를 만들기 위한
"설계도(붕어빵 틀)"라는 것을 기억하세요.

```
docker images
```

실행 결과 예시:

```
IMAGE                ID             DISK USAGE   CONTENT SIZE   EXTRA
hello-world:latest   e2ac70e7319a       10.1kB             0B    U
```

> Docker 버전에 따라 컬럼 구성이 다르게 보일 수 있습니다(예전 버전은
> `REPOSITORY TAG IMAGE ID CREATED SIZE` 형식). 어떤 포맷이든 `hello-world` 이미지가 목록에
> 있고, 용량이 몇 KB 수준으로 매우 작다는 점에 주목하세요 — 컨테이너 이미지가 왜 가상머신(VM)보다
> 훨씬 가벼운지 직접 확인한 것입니다.

**[3] 컨테이너 목록 확인하기**

`docker ps -a`는 실행이 끝나 종료된 컨테이너까지 전부(all) 보여줍니다.

```
docker ps -a
```

실행 결과 예시:

```
CONTAINER ID   IMAGE         COMMAND    CREATED         STATUS                     PORTS     NAMES
3fc446c375c3   hello-world   "/hello"   5 minutes ago   Exited (0) 5 minutes ago             unruffled_khayyam
```

STATUS가 "Exited (0)"인 것은 정상입니다. hello-world는 인사 메시지를 출력하고 할 일을 마쳤기
때문에 자동으로 종료된 것이며 오류가 아닙니다. PORTS 칸이 비어 있는 것도 정상입니다 —
hello-world는 네트워크 포트를 사용하지 않습니다.

**[4] (심화, 선택) 조금 더 살펴보기**

시간이 남았다면 아래 명령어도 실행해보세요.

```
docker --version        # 현재 Docker 버전 확인
docker info             # Docker 엔진의 상세 정보(컨테이너/이미지 개수 등) 확인
docker run hello-world  # 다시 한 번 실행해보면 "Pulling" 과정 없이 바로 실행됨
```

마지막 줄을 실행하면 "Pulling" 과정 없이 바로 결과가 나오는 것을 확인할 수 있습니다 — 이미 로컬에
이미지가 있기 때문에 다운로드가 생략된 것입니다.

## Part B. 개인 VM 실습

0주차에 배포받은 개인 로컬 VM에 접속해서, Docker와 Git이 정상 설치되어 있는지 마지막으로
점검해주세요.

```
multipass shell cloud-lab
```

VM 접속 후, Killercoda와 동일하게 아래 명령어를 실행해서 결과를 비교해보세요.

```
docker run hello-world
docker images
docker ps -a
```
