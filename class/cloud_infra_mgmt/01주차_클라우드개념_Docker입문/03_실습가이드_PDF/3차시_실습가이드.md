# 1주차 3차시 실습가이드

## 개요

오늘 배운 핵심 개념은 "컨테이너는 사실 특별한 게 아니라, 호스트 OS 위에서 돌아가는 그냥 일반
프로세스"라는 것이었습니다. 다만 자기만의 파일시스템·네트워크·프로세스 목록을 '보게' 격리되어
있을 뿐입니다. 오늘은 이 개념을 nginx라는 실제 웹 서버 컨테이너로 직접 확인하고,
`docker inspect`로 IP 주소를 찾아냅니다.

**이 실습은 이번 주차 정식 VM 과제입니다.** Killercoda에서 먼저 연습해보고, 이후 개인 로컬 VM에서
동일하게 실행한 결과를 제출해야 합니다. 소요시간은 Killercoda 15분 + VM 안내 5분 + 제출 5분입니다.

## Part A. Killercoda 실습

LMS > 1주차 > 3차시 > `05_Killercoda_링크`의 URL로 접속한 뒤 아래 순서대로 진행하세요.

> 이 세션은 **60분 제한**이 있습니다. 초기화되어도 VM에서 이어서 진행하면 됩니다.

**[1] nginx 컨테이너 실행하기**

`-d`는 백그라운드로 실행하라는 뜻이고, `--name web`은 컨테이너에 "web"이라는 이름을 붙이는
것입니다.

```
docker run -d --name web nginx
```

`nginx` 이미지가 로컬에 없으면 자동으로 pull한 뒤, 백그라운드에서 컨테이너를 실행합니다.
프롬프트가 바로 돌아오면 정상입니다.

**[2] 실행 중인 컨테이너 확인하기**

```
docker ps
```

STATUS 칸이 `Up ...` 형태로 나오면 정상입니다. 앞서 실습했던 `hello-world`와 달리, nginx는 웹
서버 프로세스가 계속 떠 있는 컨테이너이기 때문에 종료되지 않고 "Up" 상태를 유지합니다.

**[3] docker inspect로 IP 주소 확인하기**

컨테이너는 기본적으로 격리되어 있어서 밖에서 내부 상태가 잘 보이지 않습니다. `docker inspect`는
그 컨테이너의 IP 주소, 마운트된 볼륨, 환경변수, 현재 상태 같은 정보를 전부 JSON 형태로 보여주는
명령어입니다. 정보가 굉장히 많으니, IP 주소만 뽑아서 확인해보겠습니다.

```
docker inspect web | grep IPAddress
```

실행 결과 예시:

```
            "SecondaryIPAddresses": null,
            "IPAddress": "172.17.0.2",
                    "IPAddress": "172.17.0.2",
```

`IPAddress` 값이 이 nginx 컨테이너에 할당된 내부 IP입니다. 실무에서 컨테이너가 이상하게 동작할
때 가장 먼저 치는 명령어가 바로 이 `docker inspect`입니다.

## Part B. 개인 VM 실습 (필수 제출)

개인 VM(cloud-lab)에서 동일하게 아래 순서를 실행하고, 결과를 캡처하거나 GitHub 링크로 LMS 과제
게시판에 제출해주세요.

```
multipass shell cloud-lab
docker run -d --name web nginx
docker ps
docker inspect web | grep IPAddress
```

**생각해볼 질문**: Killercoda에서 나온 IP와 VM에서 나온 IP가 다를 텐데, 왜 다를까요? 정답은 —
서로 다른 컨테이너 환경이라 각자 독립적인 네트워크 공간을 갖기 때문입니다. 오늘 배운 "격리"라는
개념이 여기서도 그대로 적용됩니다.

## 제출 안내
