# 1주차 1차시 실습가이드

## 개요

오늘은 아직 Docker를 다루지 않고, 앞으로 15주 동안 계속 쓰게 될 **터미널 환경 자체**에 먼저
익숙해지는 시간입니다. Killercoda 터미널도, 여러분이 로그인한 로컬 VM도 전부 가상화 기술로
만들어진 '가상 컴퓨터'라는 것을, 아래 명령어들로 직접 확인합니다. 소요시간은 Killercoda 15분 +
VM 안내 5분입니다.

## Part A. Killercoda 실습

LMS > 1주차 > 1차시 > `05_Killercoda_링크`의 URL로 접속한 뒤 아래 순서대로 진행하세요.

> 이 세션은 **60분 제한**이 있습니다. 실습 중 시간이 종료되어도 당황하지 마세요 — 오늘 실습은
> 짧게 끝나므로 문제 없지만, 만약 중간에 끊기면 LMS의 링크로 다시 접속해 이어서 진행하면 됩니다.

**[1] 내 계정 확인하기**

`whoami`로 지금 내가 어떤 계정으로 접속했는지 확인합니다.

```
whoami
```

실행 결과 예시:

```
root
```

지금 여러분은 이 가상 서버에 `root` 계정으로 접속해있는 상태입니다.

**[2] 리눅스 시스템 정보 확인하기**

`uname -a`로 이 리눅스 시스템의 정보(커널 이름, 버전, 아키텍처 등)를 확인합니다.

```
uname -a
```

실행 결과 예시:

```
Linux ubuntu 5.15.0-generic #1 SMP x86_64 GNU/Linux
```

이 한 줄에 커널 이름, 호스트명, 커널 버전, CPU 아키텍처 정보가 모두 담겨 있습니다.

**[3] CPU 코어 수 확인하기**

`nproc`으로 이 가상 서버에 할당된 CPU 코어 수를 확인합니다.

```
nproc
```

실행 결과 예시:

```
2
```

이 숫자는 여러분의 실제 PC 코어 수가 아니라, 이 Killercoda 가상 환경에 **할당된** 코어 수입니다 —
가상화 기술이 물리 서버의 자원을 이렇게 정해진 만큼씩 나눠준다는 것을 직접 확인한 것입니다.

**[4] 메모리 용량 확인하기**

`free -h`로 이 가상 서버에 할당된 메모리 용량을 확인합니다. (`-h`는 사람이 보기 편한 단위로
보여주는 옵션입니다.)

```
free -h
```

실행 결과 예시:

```
              total        used        free      shared  buff/cache   available
Mem:           3.8Gi       200Mi       3.2Gi       1.0Mi       400Mi       3.4Gi
Swap:             0B          0B          0B
```

`nproc`과 마찬가지로, 이 메모리 용량도 이 가상 환경에 딱 할당된 만큼만 보입니다.

## Part B. 개인 VM 실습 — 0주차 VM 환경 최종 점검

Killercoda 실습이 끝났으면, 0주차에 배포받은 개인 로컬 VM을 마지막으로 점검합니다.

본인 PC 터미널(Windows는 PowerShell, Mac은 터미널 앱)에서 VM에 접속합니다.

```
multipass shell cloud-lab
```

프롬프트가 `ubuntu@cloud-lab:~$` 형태로 바뀌면 접속 성공입니다. 접속 후 아래 두 명령어를
차례로 실행하세요.

```
docker --version
git --version
```

두 명령어 모두 오류 없이 버전 정보가 출력되면 0주차 VM 환경 구성이 완료된 것입니다. 앞으로 매주
이 VM에서 심화 과제를 진행합니다.

**문제가 해결되지 않는다면?**

1. `06_로컬VM_과제복습` 폴더의 안내 문서를 다시 확인
2. `07_오류FAQ` 폴더에서 동일 증상 검색
3. 그래도 해결이 안 되면 LMS Q&A 게시판에 오류 메시지 스크린샷과 함께 질문 게시 (48시간 내 답변 원칙)
