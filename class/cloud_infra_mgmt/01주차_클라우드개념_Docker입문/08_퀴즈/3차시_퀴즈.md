# 1주차 3차시 — Docker 데몬·nginx 실습 퀴즈 (OX·단답형 8문항)

- 범위: 1주차 3차시(Docker 데몬 동작 원리, 컨테이너=격리된 프로세스, nginx 실습, docker inspect)
- 형식: OX 5문항 + 단답형 3문항
- 용도: LMS 자동채점 퀴즈. 수업 중 함께 풀고 바로 정답·해설을 확인합니다.

---

## OX 문제 (1~5번)

**1.** `docker run nginx`를 실행하면, Docker 데몬은 먼저 로컬에 이미지가 있는지 확인하고 없으면
Registry에서 pull한다. ( )

**2.** 컨테이너는 VM처럼 별도의 완전한 운영체제를 새로 부팅해서 만들어진다. ( )

**3.** 컨테이너를 지운다는 것은, 격리된 일반 프로세스 하나를 종료하는 것과 같다. ( )

**4.** `docker run -d --name web nginx`에서 `-d` 옵션은 컨테이너 이름을 지정하는 옵션이다. ( )

**5.** `docker inspect`는 컨테이너의 IP 주소, 마운트된 볼륨, 환경변수 등을 확인할 수 있는
명령어이다. ( )

## 단답형 문제 (6~8번)

**6.** 리눅스의 어떤 기술을 이용해서, 컨테이너 안에서만 보이는 격리된 실행 공간(파일시스템·
네트워크·프로세스 목록)을 만드나요?

**7.** `docker inspect web | grep IPAddress`처럼, 명령어 출력 결과가 너무 길 때 원하는 항목만
걸러서 보고 싶을 때 사용하는 명령어(파이프 뒤에 오는 것)는 무엇인가요?

**8.** 오늘 배운 개념에 따르면, 컨테이너는 사실 특별한 게 아니라 무엇 위에서 돌아가는 "그냥 ○○"
일 뿐이라고 했나요? (빈칸에 들어갈 표현을 쓰세요.)

---

## 정답 및 해설

| 번호 | 정답 | 해설 |
|---|---|---|
| 1 | O | 이미지 확인 → 없으면 pull → 파일시스템 준비 → 네임스페이스로 격리된 공간 생성 → 프로세스 실행 순서로 진행된다. |
| 2 | X | 컨테이너는 호스트 OS 위에서 돌아가는 일반 프로세스일 뿐, 별도의 OS를 부팅하지 않는다. |
| 3 | O | 컨테이너 삭제는 VM처럼 OS를 끄는 게 아니라, 격리된 프로세스 하나를 종료하는 것과 같다. |
| 4 | X | `-d`는 백그라운드(detached) 실행 옵션이다. 이름을 지정하는 옵션은 `--name`이다. |
| 5 | O | `docker inspect`는 컨테이너의 상세 설정 정보를 JSON 형태로 전부 보여준다. |
| 6 | 네임스페이스(Namespace) | 리눅스 커널 기능으로, 프로세스가 볼 수 있는 자원을 격리시켜주는 기술이다. |
| 7 | `grep` | 출력 결과 중 특정 문자열이 포함된 줄만 걸러서 보여주는 명령어다. |
| 8 | 일반 프로세스 | 컨테이너는 호스트 OS 위에서 돌아가는 그냥 일반 프로세스이며, 자기만의 자원을 "보게" 격리되어 있을 뿐이다. |
