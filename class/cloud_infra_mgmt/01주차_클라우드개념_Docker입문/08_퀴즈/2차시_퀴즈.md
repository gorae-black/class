# 1주차 2차시 — 컨테이너·Docker 아키텍처 퀴즈 (OX·단답형 8문항)

- 범위: 1주차 2차시(컨테이너 구조, VM vs 컨테이너 비교, Docker 아키텍처)
- 형식: OX 5문항 + 단답형 3문항
- 용도: LMS 자동채점 퀴즈. 수업 중 함께 풀고 바로 정답·해설을 확인합니다.

---

## OX 문제 (1~5번)

**1.** 컨테이너는 VM과 마찬가지로 각자 완전한 Guest OS를 가지고 있다. ( )

**2.** 컨테이너는 호스트 OS의 커널을 여러 컨테이너가 함께 공유한다. ( )

**3.** 격리 수준만 놓고 보면 컨테이너가 VM보다 더 강하게 격리된다. ( )

**4.** Docker Image는 읽기 전용이며, Container는 그 Image를 실제로 실행한 상태이다. ( )

**5.** Docker Hub 같은 저장소는 Docker 생태계에서 "Registry"라고 부른다. ( )

## 단답형 문제 (6~8번)

**6.** VM과 비교했을 때 컨테이너의 용량과 부팅 속도는 각각 어느 정도인가요? (강의에서 제시한
대략적인 수치로 답하세요.)

**7.** 강의에서 든 비유로, Image와 Container는 각각 붕어빵의 무엇에 해당하나요?

**8.** Docker를 구성하는 네 가지 요소(Docker Engine 포함) 중, Image와 Container를 제외한 나머지
두 가지는 무엇인가요?

---

## 정답 및 해설

| 번호 | 정답 | 해설 |
|---|---|---|
| 1 | X | 컨테이너는 Guest OS 없이 호스트 OS의 커널을 공유한다. Guest OS를 갖는 건 VM이다. |
| 2 | O | 컨테이너는 앱 실행에 필요한 코드·라이브러리만 담고, 커널은 호스트와 공유한다. |
| 3 | X | 격리는 VM이 더 강하다. 컨테이너는 커널을 공유하는 만큼 격리 수준이 상대적으로 약하다. |
| 4 | O | Image(설계도, 읽기 전용)를 실행한 상태가 Container(실체)다. |
| 5 | O | Registry는 이미지를 저장·공유하는 저장소이며, Docker Hub가 대표적이다. |
| 6 | 용량은 수십 MB~수백 MB, 부팅 속도는 1초 내외 | VM(수 GB~수십 GB, 수십 초~수 분)과 비교해 훨씬 가볍고 빠르다. |
| 7 | Image = 붕어빵 틀, Container = 실제로 구워진 붕어빵 | 같은 틀(Image) 하나로 여러 붕어빵(Container)을 만들 수 있다는 비유. |
| 8 | Docker Engine, Registry | Docker Engine은 이미지 다운로드·컨테이너 관리를 담당하는 핵심 엔진, Registry는 이미지 저장소다. |
