# 11주차 2차시 — Docker Compose로 Jenkins 설치 퀴즈

- 범위: 11주차 2차시(docker-compose.yml로 Jenkins 영구 설치)
- 형식: OX 5문항 + 단답형 3문항
- 용도: LMS 자동채점 퀴즈. 수업 중 함께 풀고 바로 정답·해설을 확인합니다.

---

## OX 문제 (1~5번)

**1.** 1차시에 Killercoda에서 사용한 Jenkins는 컨테이너를 껐다 켜도 데이터가 유지되는 영구
컨테이너였다. ( )

**2.** docker-compose.yml에서 `jenkins_home`을 Named Volume으로 지정하면, 컨테이너를 껐다 켜도
Jenkins 설정과 데이터가 유지된다. ( )

**3.** `/var/run/docker.sock`을 Jenkins 컨테이너에 마운트하면, Jenkins가 컨테이너 안에서도 호스트의
Docker를 직접 제어할 수 있다. ( )

**4.** `JAVA_OPTS=-Xmx512m` 설정은 Jenkins가 사용하는 힙 메모리를 512MB로 제한하는 옵션이다. ( )

**5.** 오늘(2차시) 실습의 필수 제출물은 플러그인 설치와 관리자 계정 생성까지 완료한 화면이다. ( )

## 단답형 문제 (6~8번)

**6.** docker-compose.yml에서 Jenkins 웹 UI 접속에 사용되는 포트 번호는 무엇인가요?

**7.** Jenkins 컨테이너의 초기 관리자 비밀번호를 확인하기 위해 실행하는 명령어는 무엇인가요?

**8.** Jenkins 컨테이너를 백그라운드로 실행(기동)하기 위해 사용하는 명령어는 무엇인가요?

---

## 정답 및 해설

| 번호 | 정답 | 해설 |
|---|---|---|
| 1 | X | 1차시의 Jenkins는 `docker run`으로 띄운 **임시** 컨테이너로, Killercoda 세션이 끝나면 데이터도 함께 사라졌다. |
| 2 | O | Named Volume(`jenkins_home:/var/jenkins_home`)을 지정하면 컨테이너를 껐다 켜도 데이터가 유지된다. |
| 3 | O | 호스트의 Docker 데몬과 통신하는 소켓을 그대로 마운트하면, Jenkins가 호스트의 Docker를 직접 제어할 수 있다(13주차 파이프라인의 핵심 원리). |
| 4 | O | Jenkins는 자바로 만들어졌으며, 이 옵션으로 힙 메모리를 512MB로 제한해 13~14주차에 minikube와 동시에 띄울 때를 대비한다. |
| 5 | X | 오늘 필수 제출물은 초기 관리자 비밀번호를 로그인 화면에 입력하는 화면까지다. 플러그인 설치·계정 생성은 다음 3차시에 진행한다. |
| 6 | 8080 | `ports: ["8080:8080", "50000:50000"]`에서 8080이 웹 UI 포트다. |
| 7 | `docker compose logs jenkins` | 이 명령으로 출력되는 로그에서 초기 관리자 비밀번호를 확인할 수 있다. |
| 8 | `docker compose up -d` | `-d` 옵션으로 백그라운드에서 Jenkins 컨테이너를 실행한다. |
