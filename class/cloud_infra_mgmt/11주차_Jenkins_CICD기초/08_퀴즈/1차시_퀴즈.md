# 11주차 1차시 — CI/CD 개념과 Jenkins 아키텍처 퀴즈

- 범위: 11주차 1차시(CI/CD 개념, Jenkins 아키텍처)
- 형식: OX 5문항 + 단답형 3문항
- 용도: LMS 자동채점 퀴즈. 수업 중 함께 풀고 바로 정답·해설을 확인합니다.

---

## OX 문제 (1~5번)

**1.** CI(지속적 통합)는 코드가 바뀔 때마다 자동으로 빌드하고 테스트해서 문제를 빨리 발견하는
것이다. ( )

**2.** CD(지속적 배포)는 빌드된 결과물을 사람이 직접 확인한 뒤 손으로 서버에 옮겨 배포하는
것이다. ( )

**3.** Jenkins의 Job은 '무엇을, 어떻게 빌드·배포할지'를 정의한 단위이다. ( )

**4.** Jenkins의 Build는 Job이 실제로 한 번 실행된 결과이며, 성공/실패와 로그, 산출물이
남는다. ( )

**5.** 오늘(1차시) 수업에서는 개인 VM에 Jenkins를 설치하는 실습을 진행한다. ( )

## 단답형 문제 (6~8번)

**6.** Jenkins의 핵심 구성요소 중, Git 연동·Docker 연동처럼 Jenkins의 기능을 확장해주는 부품을
부르는 용어는 무엇인가요?

**7.** 이번 학기 Jenkins 활용 로드맵에서, 12주차에 배우는 핵심 내용은 무엇인가요?

**8.** CI와 CD의 영문 풀네임을 각각 쓰세요.

---

## 정답 및 해설

| 번호 | 정답 | 해설 |
|---|---|---|
| 1 | O | CI는 코드 변경마다 자동으로 빌드·테스트해서 문제를 빨리 발견하는 것이다. |
| 2 | X | CD는 빌드된 결과물을 **자동으로** 실제 서비스 환경까지 배포하는 것이다. 사람이 손으로 옮기는 것이 아니다. |
| 3 | O | Job은 '무엇을, 어떻게 빌드·배포할지'를 정의한 단위다. |
| 4 | O | Build는 Job이 실행될 때마다 쌓이는 실행 이력이며, 성공/실패, 로그, 산출물이 남는다. |
| 5 | X | 오늘은 개념과 Killercoda 임시 Jenkins 컨테이너로 UI 구조만 익히며, 개인 VM에는 아직 Jenkins를 설치하지 않는다. |
| 6 | Plugin | Plugin은 Git 연동, Docker 연동처럼 Jenkins의 기능을 확장해주는 부품이다. |
| 7 | Jenkinsfile로 빌드 과정을 코드로 작성하고, GitHub과 자동 연동 | 로드맵상 11주차(서버 설치·UI) → 12주차(Jenkinsfile·GitHub 연동) → 13주차(전체 파이프라인 완성) 순서다. |
| 8 | Continuous Integration, Continuous Deployment | CI는 Continuous Integration(지속적 통합), CD는 Continuous Deployment(지속적 배포)의 줄임말이다. |
