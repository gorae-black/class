# 11주차 2차시 실습가이드

## 개요

지난 1차시의 임시 Jenkins 컨테이너와 달리, 오늘은 VM에 **영구적으로** 남는 Jenkins를
`docker-compose.yml`로 설치합니다. Named Volume(`jenkins_home`)으로 데이터를 유지하고,
`/var/run/docker.sock` 마운트로 Jenkins가 호스트 Docker를 직접 제어할 수 있게 합니다.
소요시간은 개념 설명 약 25분 + VM 실습입니다.

## VM 실습

### 1. docker-compose.yml 작성

VM에 작업 디렉터리를 만들고, 아래 검증 완료된 설정 그대로 `docker-compose.yml`을 작성합니다.

```bash
mkdir -p ~/jenkins && cd ~/jenkins
```

```yaml
# docker-compose.yml
services:
  jenkins:
    image: jenkins/jenkins:lts
    ports: ["8080:8080", "50000:50000"]
    environment: ["JAVA_OPTS=-Xmx512m"]
    volumes:
      - jenkins_home:/var/jenkins_home
      - /var/run/docker.sock:/var/run/docker.sock

volumes:
  jenkins_home:
```

설정 항목 설명:

- `image: jenkins/jenkins:lts` — Jenkins의 공식 LTS(장기지원) 버전입니다.
- `ports` — 8080(웹 UI)과 50000(에이전트 통신용) 포트를 엽니다.
- `volumes`의 `jenkins_home:/var/jenkins_home` — Named Volume으로, 컨테이너를 껐다 켜도 Jenkins
  설정과 데이터가 유지됩니다(2주차 Named Volume 개념과 동일).
- `volumes`의 `/var/run/docker.sock:/var/run/docker.sock` — 호스트 Docker 데몬과 통신하는 소켓을
  그대로 마운트해서, Jenkins 컨테이너 안에서도 호스트의 Docker를 직접 제어할 수 있게 합니다
  (13주차 파이프라인에서 Jenkins가 직접 `docker build`/`push`를 실행할 때 쓰이는 핵심 원리).
- `environment`의 `JAVA_OPTS=-Xmx512m` — Jenkins(자바 프로그램)의 힙 메모리를 512MB로 제한합니다.
  13~14주차에 minikube와 Jenkins를 동시에 띄울 때 우리 VM(RAM 4GB)이 안정적으로 동작하도록 미리
  여유 공간을 확보해두는 설정입니다.

### 2. Jenkins 컨테이너 실행

```bash
docker compose up -d
```

### 3. 초기 관리자 비밀번호 확인

```bash
docker compose logs jenkins
```

로그 안에서 초기 관리자 비밀번호(랜덤 문자열)를 찾습니다. 로그가 너무 길면 아래처럼 필터링할 수
있습니다.

```bash
docker compose logs jenkins | grep -A 3 password
```

> 컨테이너가 완전히 시작되기까지 몇 초~1분 정도 걸릴 수 있습니다. 비밀번호가 안 보이면 잠시 기다린
> 후 다시 로그를 확인하세요.

### 4. 브라우저 접속 및 로그인 화면까지 진행

브라우저에서 `http://localhost:8080` (또는 VM의 접속 주소:8080)으로 접속해서, 확인한 초기 관리자
비밀번호를 입력하는 화면까지 진행합니다.

> **오늘 실습 범위**: 플러그인 설치나 관리자 계정 생성은 다음 3차시에 이어서 진행합니다. 오늘은
> 초기 비밀번호 입력 화면까지만 진행하면 됩니다.

## 제출 안내

`docker compose logs jenkins`로 확인한 초기 관리자 비밀번호를 `localhost:8080` 로그인 화면에
입력하는 화면을 캡처해서 제출합니다. 플러그인 설치·관리자 계정 생성 화면은 제출 범위가 아닙니다
(다음 3차시에 진행).
