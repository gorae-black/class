# 14주차 2차시 — ApacheBench 부하 테스트 퀴즈 (OX·단답형 10문항)

- 범위: 14주차 2차시(ApacheBench 부하 테스트, 검증된 함정, 스케일업 관찰)
- 형식: OX 6문항 + 단답형 4문항
- 용도: LMS 자동채점 퀴즈. 수업 중 함께 풀고 바로 정답·해설을 확인합니다.

---

## OX 문제 (1~6번)

**1.** `ab -n 10000 -c 100 http://...`에서 `-n`은 동시성(동시 연결 수)을, `-c`는 총 요청
수를 의미한다. ( )

**2.** 챗봇 앱이 요청당 실제 연산이 거의 없으면, `ab`로 아무리 부하를 줘도 CPU 사용률이
0%에 머무를 수 있다. ( )

**3.** 챗봇 응답 로직에 연산을 추가한 뒤에는, `git push`만 하면 12~13주차에 배운
파이프라인이 자동으로 새 버전을 배포한다. ( )

**4.** 우리 실습 VM은 2 vCPU라서, `ab` 프로세스 자체가 오히려 VM에 부담이 될 수 있다. ( )

**5.** HPA의 스케일업이 확인되려면 REPLICAS가 반드시 max값인 5개까지 늘어나야 한다. ( )

**6.** 부하를 주는 동안 `kubectl get hpa -w`로 TARGET 항목의 CPU %가 점점 올라가는 것을
실시간으로 관찰할 수 있다. ( )

## 단답형 문제 (7~10번)

**7.** ApacheBench 명령에서 동시성(동시 연결 수)을 지정하는 옵션을 쓰세요.

**8.** ApacheBench 명령에서 총 요청 수를 지정하는 옵션을 쓰세요.

**9.** "요청당 연산이 거의 없어 부하를 줘도 CPU가 오르지 않는" 문제를 해결하기 위해 오늘
함께 적용한 두 가지 조치를 쓰세요.

**10.** HPA가 Pod 수를 늘리기 시작하는 기준(조건)을 한 문장으로 쓰세요.

---

## 정답 및 해설

| 번호 | 정답 | 해설 |
|---|---|---|
| 1 | X | 반대다. `-n`은 총 요청 수(요청 총량), `-c`는 동시성(동시 연결 수)을 뜻한다. |
| 2 | O | 요청을 처리하는 데 CPU 연산이 거의 필요 없으면, 요청이 아무리 많이 와도 CPU가 바빠지지 않는다. 학생의 잘못이 아니라 원래 그렇게 동작하는 것이다. |
| 3 | O | 코드 수정 후에는 기존 파이프라인 그대로 `git push`만으로 자동 배포된다. |
| 4 | O | 2 vCPU 환경에서는 `ab` 프로세스 자체가 부담이 될 수 있어, 필요하면 `-c` 값을 30~50 정도로 낮춘다. |
| 5 | X | 목표치를 넘는 순간 1개 이상 늘어나는 것만 확인되면 충분하다. 부하 강도에 따라 2개에서 멈출 수도, 5개까지 늘어날 수도 있다. |
| 6 | O | `kubectl get hpa -w`로 TARGET %가 실시간으로 변하는 것을 관찰할 수 있다. |
| 7 | `-c` | 동시에 몇 개의 연결로 요청을 보낼지(동시성)를 지정한다. |
| 8 | `-n` | 총 몇 번 요청을 보낼지(요청 총량)를 지정한다. |
| 9 | (1) resource request를 낮게 설정 (2) 챗봇 응답 로직에 연산 추가 | 두 조치를 함께 적용해야 부하 시 CPU 사용률이 눈에 띄게 오른다. |
| 10 | CPU 사용률이 목표치(50%)를 넘을 때 | 목표치를 넘으면 replicas가 늘어나기(Scale-out) 시작한다. |
