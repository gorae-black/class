# 14주차 1차시 — HPA 개념과 오토스케일링 설정 퀴즈 (OX·단답형 10문항)

- 범위: 14주차 1차시(HPA 개념, metrics-server, resource request, HPA 생성)
- 형식: OX 6문항 + 단답형 4문항
- 용도: LMS 자동채점 퀴즈. 수업 중 함께 풀고 바로 정답·해설을 확인합니다.

---

## OX 문제 (1~6번)

**1.** HPA(Horizontal Pod Autoscaler)는 CPU 사용률 같은 지표를 보고 Pod 개수를 자동으로
늘리거나 줄이는 K8s 기능이다. ( )

**2.** HPA는 metrics-server 없이도 각 Pod의 CPU 사용률을 알 수 있다. ( )

**3.** resource request를 너무 높게 설정하면, 실제 사용률이 request 대비 %로 계산되기
때문에 목표치를 넘기기 어려워져 스케일업이 관찰되지 않는다. ( )

**4.** `kubectl autoscale deployment chatbot --cpu-percent=50 --min=1 --max=5`는 CPU
사용률 50%를 기준으로 최소 1개, 최대 5개 사이에서 Pod 수를 조절하겠다는 명령이다. ( )

**5.** HPA의 동작 원리는 4주차에서 배운 선언적 관리(목표와 현재 상태를 비교해 스스로
맞춰나가는 방식)와 같은 원리이다. ( )

**6.** 기본 minikube는 metrics-server 기능이 처음부터 활성화되어 있다. ( )

## 단답형 문제 (7~10번)

**7.** minikube에서 metrics-server를 활성화하는 명령어를 쓰세요.

**8.** metrics-server가 정상적으로 CPU 사용률을 수집하고 있는지 확인할 수 있는 명령어를
쓰세요.

**9.** HPA는 실제 CPU 사용률을 무엇 대비 %로 계산하는지 쓰세요.

**10.** 현재 HPA의 TARGET(현재/목표 %)과 REPLICAS(현재 Pod 수)를 확인하는 명령어를
쓰세요.

---

## 정답 및 해설

| 번호 | 정답 | 해설 |
|---|---|---|
| 1 | O | HPA는 CPU 사용률 등의 지표를 보고 replicas 수를 자동으로 조정하는 K8s 기능이다. |
| 2 | X | HPA가 판단을 내리려면 metrics-server가 각 Pod의 실제 CPU 사용률을 수집해야 한다. |
| 3 | O | request가 높으면 사용률(%) 계산의 분모가 커져 목표치(50%)를 넘기 어려워진다. 그래서 실습에서는 일부러 낮게(`cpu=50m`) 설정한다. |
| 4 | O | `--cpu-percent=50`이 목표치, `--min=1 --max=5`가 Pod 수의 하한/상한이다. |
| 5 | O | HPA도 '목표'와 '현재 상태'를 계속 비교해 스스로 맞춰나가는데, 다만 목표가 '고정된 replicas 수'가 아니라 'CPU 사용률'이라는 점이 다르다. |
| 6 | X | 기본 minikube에는 metrics-server 수집 기능이 꺼져 있어 `minikube addons enable metrics-server`로 활성화해야 한다. |
| 7 | `minikube addons enable metrics-server` | 이 addon을 활성화해야 HPA가 사용할 CPU 사용률 데이터가 수집된다. |
| 8 | `kubectl top pods` | 실행 시 Pod별 CPU 사용률 숫자가 보이면 metrics-server가 정상 동작 중인 것이다. |
| 9 | request(요청한 양) | HPA는 "실제 사용률"을 "요청한 양(request) 대비 %"로 계산한다. |
| 10 | `kubectl get hpa` | TARGET(현재/목표 %)과 REPLICAS(현재 Pod 수)를 실시간으로 확인할 수 있다. |
