# 14주차 3차시 실습가이드

## 개요

부하가 걸려 Pod가 여러 개로 늘어난 상태에서 그중 하나를 강제로 삭제해, 7주차에 배운
자가치유(Self-Healing)가 트래픽 폭주라는 실전 상황에서도 정상 작동하는지 라이브로
검증합니다. Scale-out(HPA)과 자가치유가 함께 동작하면, 트래픽 폭주와 장애 두 가지 위기
모두에서 서비스가 스스로 살아남는 고가용성을 이룹니다. 오늘은 14주차의 마지막이자
1~14주차 실습 전체의 마지막 수업이므로, 실습 후 전체 회고 시간도 갖습니다.

- 소요시간: 50분 (개념 설명 15분 + VM 실습 25분 + 전체 회고 10분)
- 실습 환경: VM 전용 (Killercoda 없음)
- 전제조건: 2차시에 부하를 걸어 Pod가 여러 개로 늘어난 상태(또는 HPA·chatbot Deployment)가
  살아있어야 합니다.

## VM 실습

### 1. 부하를 걸어 Pod가 여러 개인 상태 만들기

`ab`로 다시 한번 부하를 걸어 Pod가 여러 개인 상태를 만듭니다(2차시 방법 참고).

```
ab -n 10000 -c 100 http://$(minikube service chatbot --url)/
```

### 2. 현재 Pod 이름 확인

```
kubectl get pods
```

현재 떠 있는 chatbot Pod 이름 중 하나를 확인합니다.

### 3. Pod 강제 삭제

```
kubectl delete pod {파드이름}
```

### 4. 자가치유 관찰

```
kubectl get pods -w
```

삭제된 Pod 대신 새 Pod가 즉시 생성되는 과정(Terminating → 새 Pod 생성)을 관찰합니다.

### 5. 서비스 지속 여부 확인

Pod를 삭제하는 도중 아래 명령을 실행해, 서비스(curl 응답)가 완전히 끊기지 않는지 확인합니다.
Pod 하나가 죽어도 나머지 Pod들이 요청을 처리하고 있으므로 서비스는 계속 살아있어야
정상입니다.

```
curl $(minikube service chatbot --url)
```

> 실습 시간은 25분 정도이며, 시간이 남으면 여러 개의 Pod를 연속으로 삭제해보며 자가치유의
> 견고함을 더 실감해볼 수 있습니다(replicas 개수 안에서라면 몇 개를 죽여도 Deployment가
> 계속 새로 만들어줍니다).

## 제출 안내

아래 두 화면을 캡처하여 제출합니다.

1. Pod 삭제 직후 `kubectl get pods -w` 화면 (Terminating에서 새 Pod가 생성되는 과정)
2. 삭제하는 도중 `curl $(minikube service chatbot --url)` 실행 결과 (서비스가 끊기지
   않았음을 확인)

> **14주차 종합 제출**: 오늘이 14주차 마지막 시간이므로, **1차시(HPA 설정)·2차시(부하
> 테스트)·3차시(오늘, 자가치유)** 실습을 종합해서 LMS 과제 게시판에 제출하세요.
