# 14주차 1차시 실습가이드

## 개요

HPA(Horizontal Pod Autoscaler)는 CPU 사용률 같은 지표를 보고 Pod 개수를 자동으로 늘리거나
줄이는 K8s 기능입니다. HPA가 동작하려면 ① metrics-server(지표 수집)와 ② 낮은 resource
request(임계값 계산 기준)가 함께 필요합니다. 오늘은 13주차에 완성한 chatbot Deployment에 이
두 가지 사전 준비를 마치고 HPA를 생성하는 것까지 진행합니다(실제 스케일업 관찰은 다음 2차시).

- 소요시간: 50분 (개념 설명 25분 + VM 실습 20분 + 결과 정리 5분)
- 실습 환경: VM 전용 (Killercoda 없음)
- 전제조건: 13주차에 완성한 chatbot 파이프라인(Deployment)이 그대로 살아있어야 합니다.

## VM 실습

### 1. metrics-server 활성화

HPA는 각 Pod의 CPU 사용률을 알아야 판단할 수 있습니다. 기본 minikube에는 이 수집 기능이
꺼져 있으므로 addon을 활성화합니다.

```
minikube addons enable metrics-server
```

### 2. metrics-server 동작 확인

활성화가 잘 됐는지 아래 명령으로 확인합니다. 실제 Pod별 CPU 사용률 숫자가 보이면 준비가 끝난
것입니다.

```
kubectl top pods
```

> 값이 바로 보이지 않으면 metrics-server가 완전히 준비되기까지 1분 정도 걸릴 수 있습니다.
> 잠시 기다린 후 다시 시도하세요. 그래도 안 되면 `kubectl get pods -n kube-system`으로
> metrics-server Pod가 Running 상태인지 확인하세요.

### 3. chatbot resource request 설정 (낮게)

HPA는 "실제 사용률"을 "요청한 양(request) 대비 %"로 계산합니다. request를 너무 높게 잡으면
실제 사용률이 그 대비 %로 계산되기 때문에 목표치(50%)를 넘기기 어려워져서 스케일업이
관찰되지 않습니다. 그래서 오늘은 일부러 낮게 설정합니다.

```
kubectl set resources deployment chatbot -c=web --requests=cpu=50m,memory=64Mi
```

### 4. HPA 생성

```
kubectl autoscale deployment chatbot --cpu-percent=50 --min=1 --max=5
```

CPU 사용률이 50%를 넘으면 Pod를 늘리고, 최소 1개에서 최대 5개 사이에서 조정하겠다는
뜻입니다.

### 5. HPA 생성 확인

```
kubectl get hpa
```

TARGET(현재/목표 %)과 REPLICAS(현재 Pod 수)가 표시되면 준비가 끝난 것입니다.

## 제출 안내

아래 두 화면을 캡처하여 제출합니다.

1. `kubectl top pods` 결과 — CPU 사용률이 실제로 보이는 화면
2. `kubectl get hpa` 결과 — REPLICAS: 1/1 등 초기 상태가 보이는 화면

> **주의**: 다음 2차시에 오늘 만든 HPA를 실제로 트리거하는 부하 테스트를 진행합니다.
> **오늘 설정한 HPA와 chatbot Deployment를 절대 지우지 마세요.**
