# 7주차 1차시 — Ingress 개념 퀴즈 (OX·단답형 8문항)

- 범위: 7주차 1차시(Ingress 개념)
- 형식: OX 5문항 + 단답형 3문항
- 용도: LMS 자동채점 퀴즈. 수업 중 함께 풀고 바로 정답·해설을 확인합니다.

---

## OX 문제 (1~5번)

**1.** NodePort 방식으로 서비스가 여러 개 노출되어 있으면, 서비스 개수가 늘어나도 관리해야 할
포트 번호가 늘어나지 않는다. ( )

**2.** Ingress는 L7(애플리케이션 계층)에서 도메인이나 URL 경로 같은 내용을 보고 라우팅
목적지를 결정한다. ( )

**3.** Ingress를 사용하면 외부에서는 Ingress 하나의 주소만 알아도, 여러 Service를 포트 번호
없이 이용할 수 있다. ( )

**4.** Ingress 리소스와 Ingress 컨트롤러는 완전히 같은 것을 가리키는 다른 이름일 뿐이다. ( )

**5.** minikube 환경에서는 `minikube addons enable ingress` 명령으로 Ingress 컨트롤러를
활성화할 수 있다. ( )

## 단답형 문제 (6~8번)

**6.** 클러스터 외부의 요청을 받아, 도메인/경로 규칙에 따라 알맞은 Service로 안내해주는 K8s
오브젝트의 이름은 무엇인가요?

**7.** `blog.mysite.com`으로 오면 Service A로, `shop.mysite.com`으로 오면 Service B로 보내는
것처럼, 도메인 이름 자체로 목적지를 구분하는 라우팅 방식을 무엇이라 부르나요?

**8.** `kubectl get pods -n ingress-nginx` 명령에서 `-n` 옵션은 무엇을 지정하는 옵션인가요?

---

## 정답 및 해설

| 번호 | 정답 | 해설 |
|---|---|---|
| 1 | X | 서비스가 늘어날수록 관리해야 할 포트 번호도 늘어나 점점 번거로워진다. 이것이 Ingress가 필요한 이유다. |
| 2 | O | Ingress는 L7 라우팅으로, 도메인 주소나 URL 경로 같은 '내용'을 보고 목적지를 결정한다. |
| 3 | O | 외부에서는 Ingress 하나의 주소만 알면 되고, 나머지 서비스가 몇 개든 Ingress가 알아서 분배한다. |
| 4 | X | Ingress(리소스)는 규칙을 적어놓은 문서이고, Ingress 컨트롤러는 그 규칙을 읽고 실제로 트래픽을 처리하는 실행 엔진이다. |
| 5 | O | minikube 전용 편의 기능으로, 이 한 줄이면 ingress-nginx 컨트롤러가 활성화된다. |
| 6 | Ingress | 클러스터 외부 요청을 도메인/경로 규칙에 따라 알맞은 Service로 안내하는 K8s 오브젝트다. |
| 7 | 도메인(host) 기반 라우팅 | 같은 경로라도 도메인 이름 자체가 다르면 서로 다른 Service로 보내는 방식이다. |
| 8 | namespace(네임스페이스) | ingress-nginx는 별도의 namespace에 설치되므로, `-n` 옵션으로 그 namespace를 지정해 조회해야 한다. |
