# 7주차 2차시 — Ingress 라우팅 규칙 퀴즈 (OX·단답형 8문항)

- 범위: 7주차 2차시(Ingress 라우팅 규칙 실습)
- 형식: OX 5문항 + 단답형 3문항
- 용도: LMS 자동채점 퀴즈. 수업 중 함께 풀고 바로 정답·해설을 확인합니다.

---

## OX 문제 (1~5번)

**1.** Ingress YAML에서 라우팅 규칙은 `rules` 항목 아래에 host/path별로 정의한다. ( )

**2.** Ingress의 backend는 Pod에 직접 연결되며, Service를 거치지 않는다. ( )

**3.** hosts 파일에 도메인-IP를 매핑해두면, DNS 조회 없이 그 IP로 바로 연결된다. ( )

**4.** 오늘 실습에서 매핑한 `myapp.local` 도메인은, 매핑한 내 VM이 아니어도 전 세계 어디서나
접속 가능한 공인 도메인이다. ( )

**5.** 오늘 Killercoda 실습은 경로(path) 기반 라우팅으로, 개인 VM 과제는 도메인(host) 기반
라우팅으로 진행한다. ( )

## 단답형 문제 (6~8번)

**6.** `echo "$(minikube ip) myapp.local" | sudo tee -a /etc/hosts` 명령에서 `sudo`가 필요한
이유를 한 문장으로 설명하세요.

**7.** Ingress YAML의 하나의 라우팅 규칙(rule)에서, 실제로 연결할 Service 이름과 포트를
지정하는 필드 이름은 무엇인가요?

**8.** 오늘 배운 hosts 파일 매핑 실습이, 실제 공인 DNS 등록과 다른 점을 한 문장으로 설명하세요.

---

## 정답 및 해설

| 번호 | 정답 | 해설 |
|---|---|---|
| 1 | O | `rules` 아래에 `host`(도메인)나 `path`(경로)별로 라우팅 규칙을 나열한다. |
| 2 | X | Ingress는 직접 Pod에 연결하지 않고, 항상 Service를 거쳐서 연결된다. |
| 3 | O | hosts 파일에 '도메인 - IP' 짝을 직접 적어두면, DNS 조회 없이 그 IP로 바로 연결된다. |
| 4 | X | hosts 매핑은 내 VM의 파일만 수정하는 것이라, 이 도메인은 내 VM 안에서만 동작한다. 다른 컴퓨터에서는 접속되지 않는다. |
| 5 | O | Killercoda는 `/ko`, `/en` 경로 기반, 개인 VM 과제는 `myapp.local` 도메인 기반으로 진행한다. |
| 6 | (예시) `/etc/hosts`는 시스템 설정 파일이라 수정하려면 관리자(root) 권한이 필요하기 때문이다. | 핵심은 "시스템 설정 파일을 수정하려면 관리자 권한이 필요하다"는 취지 — 채점 시 이 취지가 담기면 정답 처리 |
| 7 | backend | 규칙의 `backend`에 연결할 Service 이름과 포트를 지정한다. |
| 8 | (예시) hosts 매핑은 내 VM 안에서만 동작하는 로컬 실습용 흉내이고, 공인 DNS는 전 세계 어디서나 접속할 수 있게 등록하는 것이다. | 핵심은 "동작 범위가 내 VM 안으로 한정되는가, 전 세계로 공개되는가"의 차이 — 채점 시 이 취지가 담기면 정답 처리 |
