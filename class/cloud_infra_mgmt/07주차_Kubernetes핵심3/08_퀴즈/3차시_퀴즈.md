# 7주차 3차시 — 자가치유와 4~7주 정리 퀴즈 (OX·단답형 8문항)

- 범위: 7주차 3차시(자가치유 실습), 4~7주차 종합 정리
- 형식: OX 5문항 + 단답형 3문항
- 용도: LMS 자동채점 퀴즈. 수업 중 함께 풀고 바로 정답·해설을 확인합니다.

---

## OX 문제 (1~5번)

**1.** K8s는 선언된 Pod 개수와 실제 Pod 개수를 지속적으로 비교하다가, 차이가 있으면 스스로
맞춘다. ( )

**2.** Deployment로 관리되는 Pod가 삭제되어도, 사람이 직접 재생성 명령을 입력해야 다시
생성된다. ( )

**3.** `kubectl get pods -w`의 `-w`는 Pod 상태 변화를 실시간으로 계속 화면에 출력해주는 watch
옵션이다. ( )

**4.** 자가치유로 Pod가 재생성되면, PV/PVC에 저장돼 있던 데이터도 함께 초기화되어 사라진다.
( )

**5.** minikube처럼 단일 노드로 구성된 클러스터에서도, 오늘 배운 자가치유는 노드 자체가 죽는
상황까지 해결해준다. ( )

## 단답형 문제 (6~8번)

**6.** `kubectl delete pod`로 Pod를 삭제한 후 새 Pod가 생성되는 과정은 `Pending` → ( ) →
`Running` 순서로 진행됩니다. 빈칸에 들어갈 상태를 쓰세요.

**7.** 이미지 자체에 오류가 있어서 계속 재시작만 반복하며 실패하는 상태를 가리키는 용어는
무엇인가요?

**8.** 4주차부터 7주차까지 배운 K8s 핵심 오브젝트를 주차별로 하나씩 쓰세요. (예: 4주차 -
Pod/Deployment)

---

## 정답 및 해설

| 번호 | 정답 | 해설 |
|---|---|---|
| 1 | O | K8s는 선언된 상태와 실제 상태를 끊임없이 비교하며 차이를 스스로 맞춘다. 이것이 자가치유의 원리다. |
| 2 | X | Deployment가 살아있으면 K8s가 즉시 감지하고 새 Pod를 자동으로 생성한다. 사람이 재시작시킬 필요가 없다. |
| 3 | O | `-w`는 watch의 약자로, 상태가 바뀔 때마다 화면에 계속 출력해준다. |
| 4 | X | 자가치유로 Pod가 재생성돼도, PV/PVC로 연결된 데이터는 그대로 유지된다(6주차 연결). |
| 5 | X | 오늘 배운 자가치유는 Pod 단위 복구다. 노드 자체가 죽는 경우는 다중 노드 클러스터에서 다른 노드로 Pod를 옮겨야 하는데, 이 과목에서 쓰는 minikube는 단일 노드라 이 시나리오는 다루지 않는다. |
| 6 | ContainerCreating | 삭제된 Pod 자리에 새 Pod가 Pending → ContainerCreating → Running 순서로 생성된다. |
| 7 | CrashLoopBackOff | 이미지 자체의 문제로 계속 재시작만 반복하며 실패하는 상태로, 자가치유가 고칠 수 없는 '코드 자체의 문제'다. |
| 8 | 4주차: Pod와 Deployment / 5주차: Service와 Endpoints / 6주차: ConfigMap·Secret과 PV·PVC / 7주차: Ingress와 자가치유 | 각 주차의 핵심 오브젝트 명칭이 정확히 담기면 정답 처리 |
