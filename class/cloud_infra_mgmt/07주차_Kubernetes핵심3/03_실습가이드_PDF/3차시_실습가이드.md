# 7주차 3차시 실습가이드
## 자가치유 실습과 4~7주 정리

## 개요

지난 2차시까지 Ingress로 도메인/경로 라우팅을 성공시켰습니다. 오늘은 7주차 마지막 시간이자,
4주차부터 이어온 K8s 핵심 오브젝트 단원의 마지막 시간입니다. 오늘은 K8s의 또 다른 핵심 능력인
**자가치유(Self-Healing)**를 직접 확인하고, 4주차부터 7주차까지 배운 내용을 종합 정리합니다.

- 소요시간: 15분(Killercoda) + 5분(개인 VM 과제)
- 핵심 원리: K8s는 선언된 상태(원하는 Pod 개수)와 실제 상태를 끊임없이 비교합니다. Pod가 죽거나
  누군가 실수로 삭제해도, K8s는 즉시 감지하고 새 Pod를 자동으로 생성해서 원하는 개수를 맞춥니다.
  사람이 일일이 재시작시킬 필요가 없습니다.

## Part A. Killercoda 실습

LMS > 7주차 > `05_Killercoda_링크` > `3차시_링크.md`에 안내된 URL로 접속한 뒤 아래 순서대로
진행하세요.

이 세션은 **60분 제한**이 있습니다. 실습 중 시간이 종료되어도 당황하지 말고, LMS 링크로 다시
접속해 이어서 진행하면 됩니다.

### Step 1. 관찰용 Deployment 생성

자가치유를 관찰하려면 먼저 여러 개의 Pod를 유지하는 Deployment가 있어야 합니다.

```bash
kubectl create deployment web --image=nginx --replicas=3
```

**실행 결과 예시**

```
deployment.apps/web created
```

`kubectl get pods`로 `web-...`으로 시작하는 Pod 3개가 모두 `Running` 상태가 될 때까지
기다렸다가 다음 단계로 넘어가세요.

### Step 2. 실시간 모니터링 시작

`kubectl get pods -w`의 `-w`는 watch, 즉 Pod 상태가 바뀔 때마다 화면에 계속 출력해주는
옵션입니다. 명령 끝에 `&`를 붙이면 이 감시를 백그라운드로 돌리면서 같은 터미널에서 계속 다른
명령을 입력할 수 있습니다.

```bash
kubectl get pods -w &
```

**실행 결과 예시**

```
[1] 1234
NAME                   READY   STATUS    RESTARTS   AGE
web-6f9b8c7d5-aaaaa    1/1     Running   0          2m
web-6f9b8c7d5-bbbbb    1/1     Running   0          2m
web-6f9b8c7d5-ccccc    1/1     Running   0          2m
```

`[1] 1234`처럼 백그라운드 작업 번호가 나오고, 현재 Pod 3개의 상태가 한 번 출력되면 정상입니다.
이제 이 창은 그대로 두고, 같은 터미널에서 다음 단계의 명령어를 이어서 입력하면 됩니다.

### Step 3. Pod 강제 삭제 및 자가치유 관찰

`kubectl get pods`로 출력된 Pod 이름 중 하나를 골라, 그 Pod를 강제로 삭제합니다. (아래
`{pod-name}` 자리에 방금 확인한 실제 Pod 이름을 넣으세요. 예: `web-6f9b8c7d5-aaaaa`)

```bash
kubectl delete pod {pod-name}
```

**실행 결과 예시**

```
pod "web-6f9b8c7d5-aaaaa" deleted
```

이 명령을 실행한 직후, 백그라운드로 켜둔 `-w` 창에 아래와 같은 흐름이 실시간으로 이어서
출력됩니다.

```
web-6f9b8c7d5-aaaaa    1/1     Terminating         0          3m
web-6f9b8c7d5-ddddd    0/1     Pending             0          0s
web-6f9b8c7d5-ddddd    0/1     ContainerCreating   0          0s
web-6f9b8c7d5-ddddd    1/1     Running             0          2s
```

삭제한 Pod가 `Terminating`으로 사라지자마자, K8s가 곧바로 새 이름의 Pod를 `Pending` →
`ContainerCreating` → `Running` 순서로 자동 생성해서 원래 개수(3개)를 다시 맞추는 것을
확인하세요. 아무도 손대지 않았는데 스스로 복구된 것 — 이것이 오늘 배운 자가치유입니다. 확인이
끝나면 `kill %1`로 백그라운드 watch를 종료해도 됩니다.

## Part B. 개인 VM 실습

개인 VM에서도 Part A와 동일한 순서로 진행합니다.

1. `kubectl get pods -w &`로 실시간 모니터링을 시작하세요.
2. `kubectl delete pod {pod-name}`으로 임의의 Pod를 강제로 삭제하세요.
3. Terminating부터 새 Pod가 Running이 되기까지의 과정을 화면으로 관찰하고 캡처하세요.

> **주의사항**
> 만약 minikube를 재시작한 상태로 이어서 실습한다면, 재시작 직후에는 Ingress 컨트롤러가 아직
> 준비되지 않아서 `kubectl apply`나 접속이 실패할 수 있습니다. 10~20초 정도 기다린 뒤 진행하세요.

오늘이 7주차 마지막 시간이자 K8s 단원의 마지막 수업이므로, 4주차(Pod/Deployment)부터
7주차(Ingress/자가치유)까지의 실습을 종합 정리해서 제출해주세요.

## 4~7주차 한눈에 정리

| 주차 | 핵심 오브젝트 | 배운 내용 |
|---|---|---|
| 4주차 | Pod와 Deployment | 컨테이너를 감싸는 최소 단위, 원하는 개수를 선언적으로 유지하는 방법 |
| 5주차 | Service와 Endpoints | Pod에 안정적인 접속 경로를 제공하고, 여러 Pod에 트래픽을 라운드로빈 방식으로 분산 |
| 6주차 | ConfigMap/Secret과 PV/PVC | 설정과 비밀정보를 코드에서 분리, 데이터를 영구적으로 보관 |
| 7주차 | Ingress와 자가치유 | 여러 서비스를 도메인 주소로 통합, 장애가 나도 시스템이 스스로 복구 |

다음 8주차는 **중간고사**입니다. 1~3주차 Docker와 4~7주차 Kubernetes 전체 내용을 복습한 후
온라인으로 시험을 치릅니다. 4주차부터 7주차까지 K8s 내용이 시험 범위의 절반을 차지하니, 지금까지
제출했던 실습 결과물과 각 주차의 핵심 오브젝트·명령어를 손으로 다시 쳐보면서 꼭 복습해오세요.
