# 2주차 2차시 — Bind Mount 퀴즈 (OX·단답형 7문항)

- 범위: 2주차 2차시(컨테이너 데이터 문제, Bind Mount)
- 형식: OX 4문항 + 단답형 3문항
- 용도: LMS 자동채점 퀴즈. 수업 중 함께 풀고 바로 정답·해설을 확인합니다.

---

## OX 문제 (1~4번)

**1.** 컨테이너의 파일시스템은 그 컨테이너 자신에게 속해 있어서, `docker rm`으로
컨테이너를 지우면 그 안에 저장된 파일도 함께 사라진다. ( )

**2.** Bind Mount로 컨테이너를 연결하면, VM에서 파일을 수정해도 컨테이너 안의 파일에는
아무 영향이 없다. ( )

**3.** `docker run -v {VM 경로}:{컨테이너 경로} {이미지}`에서 콜론(:) 왼쪽은 VM(호스트)
쪽 경로, 오른쪽은 컨테이너 쪽 경로다. ( )

**4.** `-p 8080:80` 옵션 없이도 VM 밖에서 `curl localhost:8080`으로 컨테이너 안의 웹
서버에 바로 접속할 수 있다. ( )

## 단답형 문제 (5~7번)

**5.** VM(호스트)의 특정 디렉토리를 컨테이너 내부의 특정 경로에 그대로 연결해서,
컨테이너를 지워도 VM에는 데이터가 그대로 남도록 하는 이 기술의 이름은 무엇인가요?

**6.** nginx 컨테이너에서 Bind Mount로 웹 페이지 파일을 연결할 때 사용하는 컨테이너
내부 경로는 무엇인가요?

**7.** Bind Mount를 사용하려고 할 때, VM 쪽 경로가 미리 존재하지 않으면 문제가 생길 수
있습니다. 그래서 Bind Mount 실습 전에 항상 먼저 실행해야 하는 명령어(예: `~/html`
폴더를 만드는 명령)를 쓰세요.

---

## 정답 및 해설

| 번호 | 정답 | 해설 |
|---|---|---|
| 1 | O | 컨테이너의 파일시스템은 컨테이너에 속해 있으므로, `docker rm`으로 컨테이너를 지우면 그 안의 파일도 함께 사라진다. |
| 2 | X | Bind Mount는 VM 디렉토리와 컨테이너 경로를 그대로 "연결"하는 것이므로, VM에서 파일을 수정하면 컨테이너 안에도 즉시 반영된다(양방향으로 실시간 연결). |
| 3 | O | `-v {VM 경로}:{컨테이너 경로}` 형식으로, 콜론 기준 왼쪽이 VM 쪽, 오른쪽이 컨테이너 쪽 경로다. |
| 4 | X | 컨테이너는 기본적으로 격리되어 있어 외부에서 바로 접속할 수 없다. `-p`로 VM의 포트를 컨테이너 포트에 연결해야 curl이나 브라우저로 접속할 수 있다. |
| 5 | Bind Mount | VM의 특정 디렉토리를 컨테이너 내부 경로에 그대로 연결하는 기능이다. |
| 6 | `/usr/share/nginx/html` | nginx는 이 경로 안의 파일들을 웹 페이지로 보여주도록 만들어져 있다. |
| 7 | `mkdir -p ~/html` (VM 쪽 경로를 미리 만들어두는 명령) | Bind Mount는 VM 쪽 경로가 반드시 미리 존재해야 하므로, 항상 먼저 만들어두는 습관이 필요하다. |
