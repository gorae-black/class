# 2주차 3차시 — Named Volume과 데이터 영속성 퀴즈 (OX·단답형 8문항)

- 범위: 2주차 3차시(Bind Mount 실시간 반영, Named Volume, Bind Mount vs Named Volume 비교)
- 형식: OX 5문항 + 단답형 3문항
- 용도: LMS 자동채점 퀴즈. 수업 중 함께 풀고 바로 정답·해설을 확인합니다.

---

## OX 문제 (1~5번)

**1.** Bind Mount로 연결된 컨테이너는 VM의 파일을 수정하면 컨테이너를 재시작해야만
변경 내용이 반영된다. ( )

**2.** Bind Mount는 파일을 "복사"하는 것이 아니라 "연결"하는 것이다. ( )

**3.** Named Volume은 `docker volume create` 명령으로 만들 수 있다. ( )

**4.** Named Volume은 Bind Mount와 달리, 데이터가 VM의 어느 경로에 저장되는지 사용자가
직접 경로를 지정해서 관리해야 한다. ( )

**5.** `docker run`에서 존재하지 않는 이름으로 `-v`를 사용하면, Docker가 자동으로 그
이름의 Named Volume을 만들어준다. ( )

## 단답형 문제 (6~8번)

**6.** `docker volume create`로 만든, Docker가 직접 관리하는 저장 공간을 부르는 이름은
무엇인가요?

**7.** Bind Mount와 Named Volume의 차이를 "누가 저장 경로를 관리하는가"의 관점에서 한
문장으로 설명하세요.

**8.** Named Volume을 컨테이너에 연결할 때 사용하는 옵션 문법을 쓰세요. (예:
`docker run -v {볼륨이름}:{컨테이너 경로} ...`)

---

## 정답 및 해설

| 번호 | 정답 | 해설 |
|---|---|---|
| 1 | X | Bind Mount는 파일을 연결하는 것이므로, VM 파일을 수정하면 컨테이너를 재시작하지 않아도 즉시 반영된다. |
| 2 | O | Bind Mount는 VM의 파일과 컨테이너가 보는 파일이 사실상 완전히 같은 파일이 되도록 "연결"하는 방식이다. |
| 3 | O | `docker volume create {이름}`으로 Docker가 관리하는 저장 공간(볼륨)을 만들 수 있다. |
| 4 | X | 반대다. Bind Mount는 사용자가 VM의 정확한 경로를 직접 지정해야 하지만, Named Volume은 실제 저장 위치를 Docker가 알아서 관리해준다. |
| 5 | O | 존재하지 않는 이름으로 `-v`를 쓰면 Docker가 자동으로 Named Volume을 만들어준다. 다만 명시적으로 `create`를 먼저 하면 어떤 볼륨이 있는지 관리하기 더 쉽다. |
| 6 | Named Volume | Docker가 직접 관리하는 저장 공간이다. |
| 7 | (예시) Bind Mount는 내가 VM 경로를 직접 지정해 관리하고, Named Volume은 Docker가 저장 위치를 알아서 관리한다. | 핵심은 "경로 관리 주체"의 차이 — 채점 시 이 취지가 담기면 정답 처리 |
| 8 | `docker run -v {볼륨이름}:{컨테이너 경로} {이미지}` | Bind Mount와 문법은 비슷하지만, 콜론 왼쪽에 VM 경로 대신 볼륨 이름을 쓴다. |
