# 2주차 3차시 실습가이드 (2주차 마지막 시간)

## 개요

지난 2차시에서 Bind Mount로 `webvol` 컨테이너를 만들었습니다. 이번 3차시에서는 VM의
`~/html/index.html` 파일만 새로운 내용으로 덮어쓰면 컨테이너를 재시작하지 않아도 웹
화면이 즉시 바뀌는 것을 직접 확인합니다. Bind Mount는 파일을 "복사"하는 게 아니라
"연결"하는 것이기 때문에, VM에서 수정하는 순간 컨테이너에서도 똑같이 바뀐 것으로
보입니다. 그다음 Bind Mount와는 조금 다른 방식인 **Named Volume**을 배웁니다.

- 소요시간: 개념 설명 25분 + Killercoda 실습 15분 + VM 과제 안내 5분 + 결과 제출 5분 (총 50분)
- 핵심 개념: Bind Mount의 실시간 반영, Named Volume(`docker volume create`, Docker가 관리하는
  저장 공간), Bind Mount vs Named Volume 비교(경로 관리 주체, 용도, 이식성)
- 이번 차시는 2주차의 마지막입니다. 실습이 끝나면 1~3차시 과제를 종합해서 제출하세요.

## Part A. Killercoda 실습

LMS > 2주차 > 05_Killercoda_링크 > 3차시_링크 에 안내된 URL로 접속해서 진행하세요.

> **참고**: 이 Killercoda 세션은 매번 새로운 환경으로 시작되기 때문에, 지난 2차시의
> `webvol` 컨테이너가 남아있지 않습니다. 그래서 첫 단계에서 2차시 내용을 빠르게 다시
> 만든 뒤 이어서 진행합니다. (개인 VM에서는 지난 시간 컨테이너가 그대로 남아있으니, 다시
> 만들 필요 없이 바로 다음 단계부터 이어서 하면 됩니다.)
>
> 이 세션은 60분 제한이 있습니다. 초기화되어도 VM에서 이어서 진행하면 됩니다.

### 1단계. 지난 2차시 환경 재현하기

본격적인 실습에 앞서, 지난 2차시에서 만들었던 Bind Mount 컨테이너를 이 새 환경에 그대로
재현합니다. (개인 VM에서 실습 중이라면 이 컨테이너가 이미 실행 중이니 이 단계는 건너뛰고
바로 2단계로 넘어가면 됩니다.)

```
mkdir -p ~/html
echo '<h1>Hello Cloud!</h1>' > ~/html/index.html
docker run -d -p 8080:80 -v ~/html:/usr/share/nginx/html --name webvol nginx
```

세 명령어 모두 특별한 오류 메시지 없이 지나가고, 마지막 `docker run`에서 컨테이너 ID
해시 값이 출력되면 정상입니다. `curl localhost:8080`을 쳐보면 `<h1>Hello Cloud!</h1>`가
나오는지 확인해볼 수 있습니다.

### 2단계. 실시간 반영 확인하기

이제 VM(이 터미널)의 `~/html/index.html` 파일을 새로운 내용으로 덮어씁니다. 컨테이너를
재시작하지 않고 파일만 바꿔서, 웹 화면이 어떻게 되는지 확인해보겠습니다.

```
echo '<h1>Updated!</h1>' > ~/html/index.html
curl localhost:8080
```

**실행 결과 예시**

```
<h1>Updated!</h1>
```

컨테이너를 재시작하지 않았는데도 "Updated!"로 바뀐 것이 보이면 성공입니다. Bind Mount는
파일을 복사하는 게 아니라 연결하는 것이기 때문에, VM의 파일과 컨테이너가 보는 파일이
사실은 완전히 같은 파일입니다.

### 3단계. Named Volume 만들기

Named Volume은 `docker volume create`로 만드는, Docker가 직접 관리하는 저장
공간입니다. Bind Mount처럼 VM의 정확한 경로를 직접 지정할 필요가 없습니다.

```
docker volume create mydata
```

**실행 결과 예시**

```
mydata
```

방금 만든 볼륨의 이름이 그대로 출력되면 정상적으로 생성된 것입니다. 이 데이터가 VM
어디에 저장되는지는 Docker가 알아서 관리하므로, 우리는 정확한 경로를 신경 쓸 필요가
없습니다.

### 4단계. Named Volume으로 컨테이너 실행하기

방금 만든 `mydata` 볼륨을 사용해 새 컨테이너를 실행합니다. Bind Mount와 문법은
비슷하지만, `-v` 왼쪽에 VM 경로 대신 볼륨 이름을 씁니다.

```
docker run -d -v mydata:/usr/share/nginx/html --name webvol2 nginx
```

컨테이너의 긴 ID 해시 값이 출력되고 프롬프트가 바로 돌아오면 정상입니다. `docker ps`로
`webvol2`가 `Up` 상태로 실행 중인지 확인해보세요. Bind Mount는 내가 VM 경로를 직접
관리하고, Named Volume은 Docker가 관리한다는 차이를 오늘 두 컨테이너(`webvol`,
`webvol2`)로 직접 비교해본 것입니다.

여기까지가 오늘의 Killercoda 실습이자, 2주차 실습의 마지막입니다.

## Part B. 개인 VM 실습

개인 로컬 VM(cloud-lab)에서 오늘 실습을 동일하게 수행합니다. 지난 2차시 컨테이너가
그대로 남아있으므로 재현 단계는 건너뛰고 바로 진행하면 됩니다.

1. VM에 접속합니다.

   ```
   multipass shell cloud-lab
   ```

2. `webvol`의 `index.html`을 수정하고 즉시 반영되는지 확인합니다.

   ```
   echo '<h1>Updated!</h1>' > ~/html/index.html
   curl localhost:8080
   ```

3. Named Volume을 만들고 새 컨테이너를 실행합니다.

   ```
   docker volume create mydata
   docker run -d -v mydata:/usr/share/nginx/html --name webvol2 nginx
   docker ps
   ```

4. `webvol2`가 `Up` 상태로 나오는지 확인합니다.

**제출 필수 항목**: `webvol`의 index.html 수정 후 즉시 반영되는 화면(`curl` 결과)과,
Named Volume으로 만든 `webvol2` 컨테이너 실행 결과 화면을 각각 캡처하세요.
