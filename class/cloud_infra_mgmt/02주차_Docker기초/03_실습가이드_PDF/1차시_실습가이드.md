# 2주차 1차시 실습가이드

## 개요

1주차에서 `docker run`으로 컨테이너를 실행하고 `docker inspect`로 내부를 점검하는 방법을
배웠습니다. 이번 1차시에서는 컨테이너를 멈추고(stop), 다시 켜고(start), 필요 없으면
지우는(rm) **생명주기(lifecycle)** 명령어와, 실행 중인 컨테이너 내부를 들여다보는
`logs`·`exec`를 다룹니다. 특히 "컨테이너를 stop해도 데이터는 사라지지 않지만, rm으로
지우면 완전히 사라진다"는 문제의식을 확실히 챙겨두세요 — 이 문제의식이 다음 2·3차시
(Bind Mount, Named Volume)로 그대로 이어집니다.

- 소요시간: 개념 설명 25분 + Killercoda 실습 15분 + VM 과제 안내 5분 + 결과 제출 5분 (총 50분)
- 핵심 개념: 컨테이너 상태(Created→Running→Stopped→Removed), `docker run` = `create` + `start`,
  `docker ps` vs `docker ps -a`, `docker stop`/`start`/`rm`/`rm -f`, `docker logs`, `docker exec -it`

## Part A. Killercoda 실습

LMS > 2주차 > 05_Killercoda_링크 > 1차시_링크 에 안내된 URL로 접속해서 진행하세요.

> 이 세션은 60분 제한이 있습니다. 오늘 실습은 짧게 끝나므로 문제 없지만, 만약 중간에
> 끊기면 LMS의 링크로 다시 접속해 이어서 진행하면 됩니다.

### 1단계. 컨테이너 실행하기

`docker run -d --name web2 nginx`로 컨테이너를 하나 새로 실행합니다. `-d`는 백그라운드
실행, `--name web2`는 컨테이너에 "web2"라는 이름을 붙이는 옵션입니다.

```
docker run -d --name web2 nginx
```

`nginx` 이미지가 로컬에 이미 있으므로(1주차 3차시에서 받아둔 이미지) 바로 실행되며,
컨테이너의 긴 ID 해시 값이 출력되고 프롬프트가 바로 돌아옵니다.

이 컨테이너로 앞으로 stop → start → logs → exec까지 이어서 실습합니다.

### 2단계. 컨테이너 멈추기 — `docker stop`

`docker stop`으로 실행 중인 컨테이너를 멈춥니다. 멈춰도 컨테이너와 그 안의 파일은
사라지지 않는다는 점을 기억하세요 — 완전히 지우는 것은 `docker rm`의 역할입니다.

```
docker stop web2
```

**실행 결과 예시**

```
web2
```

멈춘 컨테이너의 이름이 그대로 출력되면 정상적으로 정지된 것입니다.

### 3단계. 상태 확인하기 — `docker ps -a`

`docker ps -a`로 방금 멈춘 `web2`의 상태가 어떻게 바뀌었는지 확인합니다. `docker
ps`(옵션 없이)는 실행 중인 것만 보여주므로, 정지된 컨테이너까지 보려면 반드시 `-a`를
붙여야 합니다.

```
docker ps -a
```

**실행 결과 예시**

```
CONTAINER ID   IMAGE     COMMAND                  CREATED         STATUS                      PORTS     NAMES
6b1f2a9c4e21   nginx     "/docker-entrypoint.…"   2 minutes ago   Exited (0) 5 seconds ago              web2
```

STATUS 칸이 `Exited`로 바뀐 것을 확인하세요. 오류가 아니라 `docker stop`이 정상적으로
동작한 결과입니다.

### 4단계. 다시 켜기 — `docker start`

`docker start`로 정지된 컨테이너를 다시 켭니다. 이미 만들어져 있는 컨테이너를 그대로
재실행하는 것이므로, `docker run`처럼 이미지를 새로 pull하거나 컨테이너를 새로 만들지
않습니다.

```
docker start web2
```

**실행 결과 예시**

```
web2
```

이름이 그대로 출력되면 정상적으로 재시작된 것입니다.

### 5단계. 다시 상태 확인하기

다시 `docker ps -a`로 상태를 확인해서, `web2`가 정말 다시 살아났는지 확인합니다.

```
docker ps -a
```

**실행 결과 예시**

```
CONTAINER ID   IMAGE     COMMAND                  CREATED         STATUS         PORTS     NAMES
6b1f2a9c4e21   nginx     "/docker-entrypoint.…"   3 minutes ago   Up 5 seconds             web2
```

STATUS 칸이 다시 `Up ...` 형태로 바뀌었다면 정상입니다. stop → start를 거쳐도 컨테이너
ID와 이름은 그대로 유지된다는 점도 함께 확인하세요.

### 6단계. 로그 확인하기 — `docker logs`

`docker logs`는 그 컨테이너가 지금까지 출력한 로그를 보여줍니다. 실행 중인 프로세스
안에서 어떤 일이 벌어지고 있는지 "창문 너머로 구경"하는 방법입니다. (`-f` 옵션을 붙이면
로그를 실시간으로 계속 지켜볼 수 있습니다.)

```
docker logs web2
```

**실행 결과 예시**

```
/docker-entrypoint.sh: /docker-entrypoint.d/ is not empty, will attempt to perform configuration
/docker-entrypoint.sh: Configuration complete; ready for start up
2026/07/24 10:00:00 [notice] 1#1: nginx/1.27.0
2026/07/24 10:00:00 [notice] 1#1: start worker processes
```

nginx 웹 서버가 시작되며 출력한 초기화 로그가 보이면 정상입니다. (버전이나 시각은 실습
환경에 따라 다르게 보일 수 있습니다.)

### 7단계. 컨테이너 내부 들어가기 — `docker exec`

`docker exec -it web2 bash`는 아예 그 컨테이너 "안으로" 직접 들어가는 명령어입니다.
logs가 "창문 너머로 구경하기"라면, exec는 "문 열고 직접 들어가기"입니다.

```
docker exec -it web2 bash
```

**실행 결과 예시**

```
root@6b1f2a9c4e21:/#
```

프롬프트가 `root@{컨테이너ID}:/#` 형태로 바뀌면, 이제 여러분은 web2 컨테이너 내부에
들어와 있는 것입니다. 컨테이너 안에서 자유롭게 명령어를 쳐볼 수 있습니다. 다 확인했으면
`exit`을 쳐서 다시 원래 터미널로 나옵니다.

```
exit
```

프롬프트가 원래대로 돌아오면, 컨테이너 밖으로 정상적으로 빠져나온 것입니다.

여기까지가 오늘의 Killercoda 실습입니다.

## Part B. 개인 VM 실습

개인 로컬 VM(cloud-lab)에서 위와 동일한 순서를 그대로 실행합니다.

1. VM에 접속합니다.

   ```
   multipass shell cloud-lab
   ```

2. Killercoda에서 진행한 것과 동일한 순서로 명령어를 차례로 입력합니다.

   ```
   docker run -d --name web2 nginx
   docker stop web2
   docker ps -a
   docker start web2
   docker ps -a
   docker logs web2
   docker exec -it web2 bash
   exit
   ```

3. 각 단계의 결과가 Killercoda에서 본 것과 같은 패턴(Exited → Up, 로그 출력, 프롬프트
   변화)으로 나오는지 확인합니다.

**제출 필수 항목**: `docker ps -a` 결과 화면과 `docker logs` 출력 화면을 캡처해서 LMS
과제 게시판에 제출하세요.
