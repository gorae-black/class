# 2주차 2차시 실습가이드

## 개요

지난 1차시에서 컨테이너를 stop하고 rm으로 지우는 것을 배우면서, "컨테이너 안에 파일을
저장해뒀는데, 지우면 그것도 같이 사라지는 거 아닌가?"라는 의문이 들었을 것입니다.
맞습니다 — 컨테이너의 파일시스템은 그 컨테이너 자신에게 속해 있어서, `docker rm`으로
컨테이너를 지우면 그 안에 저장했던 파일도 함께 사라집니다. 이번 2차시에서는 이 문제를
**Bind Mount**라는 기술로 해결합니다.

- 소요시간: 개념 설명 25분 + Killercoda 실습 15분 + VM 과제 안내 5분 + 결과 제출 5분 (총 50분)
- 핵심 개념: Bind Mount(= VM 디렉토리와 컨테이너 경로를 그대로 연결), `-v {VM 경로}:{컨테이너 경로}`
  문법, `-p {VM 포트}:{컨테이너 포트}` 문법

> **중요 공지**: 오늘 만드는 `webvol` 컨테이너는 **다음 3차시에도 이어서 사용**합니다.
> 실습이 끝나도 컨테이너를 지우지 말고 그대로 두세요.

---

## Part A. Killercoda 실습

LMS > 2주차 > 05_Killercoda_링크 > 2차시_링크 에 안내된 URL로 접속해서 진행하세요.

> 이 세션은 60분 제한이 있습니다. 오늘 실습은 짧게 끝나므로 문제 없지만, 만약 중간에
> 끊기면 LMS의 링크로 다시 접속해 이어서 진행하면 됩니다.

### 1단계. Bind Mount용 디렉토리 만들기

Bind Mount로 컨테이너와 연결할 VM(이 터미널) 쪽 디렉토리를 먼저 만듭니다. Bind Mount는
VM 쪽 경로가 미리 존재해야 하므로, 항상 이렇게 먼저 만들어두는 습관이 필요합니다.

```
mkdir -p ~/html
```

이 명령어는 특별한 출력 없이 프롬프트가 바로 돌아오면 정상입니다. `~/html` 폴더가 새로
만들어진 것입니다.

### 2단계. HTML 파일 만들기

방금 만든 폴더 안에 아주 간단한 HTML 파일을 하나 만듭니다. 이 파일이 곧 nginx
컨테이너가 보여줄 웹 페이지가 됩니다.

```
echo '<h1>Hello Cloud!</h1>' > ~/html/index.html
```

이 명령어도 출력 없이 프롬프트가 바로 돌아오면 정상입니다. `cat ~/html/index.html`로
내용을 확인해보면 방금 쓴 `<h1>Hello Cloud!</h1>`가 그대로 들어있는 것을 볼 수 있습니다.

### 3단계. Bind Mount로 컨테이너 실행하기

이제 Bind Mount로 방금 만든 `~/html` 디렉토리를 컨테이너 안의
`/usr/share/nginx/html` 경로에 연결하며 컨테이너를 실행합니다. nginx는 원래 이 경로
안의 파일들을 웹 페이지로 보여주도록 만들어져 있습니다.

`-v {VM 경로}:{컨테이너 경로}` 형식으로 콜론(:) 기준 왼쪽이 VM 쪽, 오른쪽이 컨테이너
쪽 경로입니다. `-p 8080:80`은 VM의 8080번 포트를 컨테이너의 80번 포트에 연결하는
옵션입니다 — 컨테이너는 기본적으로 격리되어 있어 외부에서 바로 접속할 수 없으므로, 이
옵션이 있어야 curl이나 브라우저로 접속할 수 있습니다.

```
docker run -d -p 8080:80 -v ~/html:/usr/share/nginx/html --name webvol nginx
```

컨테이너의 긴 ID 해시 값이 출력되고 프롬프트가 바로 돌아오면 정상입니다. `-d` 옵션
덕분에 터미널을 점유하지 않고 백그라운드에서 계속 실행됩니다.

### 4단계. 접속 확인하기 — `curl`

`curl`로 방금 실행한 웹 서버에 접속해서, 우리가 만든 HTML 파일이 실제로 웹 페이지로
나오는지 확인합니다.

```
curl localhost:8080
```

**실행 결과 예시**

```
<h1>Hello Cloud!</h1>
```

방금 `~/html/index.html`에 적어둔 내용이 그대로 출력되면 성공입니다. VM의 파일이 Bind
Mount를 통해 컨테이너 안의 웹 서버가 보여주는 페이지와 완전히 같은 파일이라는 것을
확인한 것입니다.

여기까지가 오늘의 Killercoda 실습입니다.

## Part B. 개인 VM 실습

개인 로컬 VM(cloud-lab)에서 위 4단계를 그대로 동일하게 수행합니다.

1. VM에 접속합니다.

   ```
   multipass shell cloud-lab
   ```

2. Killercoda에서 진행한 것과 동일한 4단계를 차례로 입력합니다.

   ```
   mkdir -p ~/html
   echo '<h1>Hello Cloud!</h1>' > ~/html/index.html
   docker run -d -p 8080:80 -v ~/html:/usr/share/nginx/html --name webvol nginx
   curl localhost:8080
   ```

3. `curl localhost:8080` 결과로 `<h1>Hello Cloud!</h1>`가 출력되는지 확인합니다.

> **주의**: `-v` 옵션의 왼쪽 VM 경로는 반드시 미리 존재해야 하므로, `mkdir` 단계를
> 건너뛰지 마세요. 또한 VM에서 `~/html` 폴더의 파일을 직접 지우면 컨테이너에서도 즉시
> 사라집니다(양방향으로 실시간 연결되어 있기 때문입니다) — 반대도 마찬가지입니다.

**제출 필수 항목**: `curl localhost:8080` 결과 화면을 캡처해서 LMS 과제 게시판에
제출하세요.

**⚠️ 컨테이너를 지우지 마세요**: 오늘 만든 `webvol` 컨테이너는 **다음 3차시에도 이어서
사용**합니다. 실습이 끝나도 `docker rm` 등으로 지우지 말고 VM에 그대로 두세요.
