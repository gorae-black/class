# 12주차 2차시 — Jenkinsfile 작성과 수동 빌드 퀴즈 (OX·단답형 10문항)

- 범위: 12주차 2차시(실전 Jenkinsfile 작성, Pipeline Job 생성, Build Now)
- 형식: OX 6문항 + 단답형 4문항
- 용도: LMS 자동채점 퀴즈. 수업 중 함께 풀고 바로 정답·해설을 확인합니다.

---

## OX 문제 (1~6번)

**1.** Jenkinsfile 기반 Job을 만들 때는 New Item에서 Freestyle project를 선택해야 한다. ( )

**2.** Checkout stage에서는 `git url: "..."` 스텝으로 GitHub 저장소를 가져온다. ( )

**3.** `sh` 스텝은 Jenkins 안에서 셸 명령어를 실행하는 스텝이다. ( )

**4.** 오늘 실습에서 사용하는 저장소는 3주차와 무관하게 완전히 새로 만든 저장소이다. ( )

**5.** Stage View에서 각 단계가 빨간색으로 표시되면 그 단계가 성공적으로 완료된 것이다. ( )

**6.** Build Now 실행 후 Console Output에서 `git clone` 로그와 `docker build` 로그를 확인할 수
있다. ( )

## 단답형 문제 (7~10번)

**7.** Pipeline Job을 만들 때 Jenkinsfile 내용을 붙여넣는 텍스트 칸의 이름은 무엇인가요?

**8.** 오늘 작성한 Jenkinsfile에서 Build stage가 실제로 실행하는 명령어를 쓰세요.

**9.** Build Now 실행 후 이미지가 실제로 만들어졌는지 VM 터미널에서 확인할 때 쓰는 명령어는
무엇인가요?

**10.** Checkout stage의 `git url` 안 `{id}` 자리에는 무엇을 넣어야 하나요?

---

## 정답 및 해설

| 번호 | 정답 | 해설 |
|---|---|---|
| 1 | X | 반드시 **Pipeline** 타입을 선택해야 한다. Freestyle을 선택하면 Pipeline script 입력란 자체가 나오지 않는다. |
| 2 | O | `git url: "https://github.com/{id}/cloud-lab.git", branch: "main"` 형태로 저장소를 가져온다. |
| 3 | O | `sh` 스텝은 셸 명령어(예: `docker build`)를 그대로 실행한다. |
| 4 | X | 3주차에 GitHub에 올렸던 `cloud-lab` 저장소(`app.py`, `Dockerfile`)를 다시 활용한다. |
| 5 | X | 초록색이 성공, 빨간색은 해당 단계에서 오류가 난 것이다. |
| 6 | O | Console Output에는 Checkout의 `git clone` 로그와 Build의 `docker build` 로그가 순서대로 출력된다. |
| 7 | Pipeline script | Pipeline 섹션의 'Pipeline script' 텍스트 칸에 Jenkinsfile 내용을 그대로 붙여넣는다. |
| 8 | `docker build -t myflask:test .` | Build stage의 `sh` 스텝이 실행하는 명령어다. |
| 9 | `docker images` | 실행하면 `myflask:test` 이미지가 실제로 만들어졌는지 목록에서 확인할 수 있다. |
| 10 | 본인의 GitHub 아이디 | `{id}` 자리에 본인 계정 아이디를 넣어야 저장소 주소가 올바르게 연결된다. |
