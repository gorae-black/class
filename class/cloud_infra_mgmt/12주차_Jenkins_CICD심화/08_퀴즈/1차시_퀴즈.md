# 12주차 1차시 — Declarative Pipeline 문법 퀴즈 (OX·단답형 10문항)

- 범위: 12주차 1차시(Jenkinsfile Declarative Pipeline 문법)
- 형식: OX 6문항 + 단답형 4문항
- 용도: LMS 자동채점 퀴즈. 수업 중 함께 풀고 바로 정답·해설을 확인합니다.

---

## OX 문제 (1~6번)

**1.** Jenkinsfile은 빌드 파이프라인을 코드(텍스트 파일)로 선언해 버전관리·재사용이 가능하게
한다. ( )

**2.** `agent any`는 파이프라인을 반드시 특정 서버 하나에서만 실행하라는 뜻이다. ( )

**3.** 파이프라인을 여러 `stage`로 나누면, Jenkins UI에서 각 stage의 성공·실패를 시각적으로 확인할
수 있다. ( )

**4.** `withCredentials { }`를 쓰면 Docker Hub 비밀번호 같은 민감정보를 Jenkinsfile에 그대로 평문으로
적어도 안전하다. ( )

**5.** 이 과목에서는 Scripted Pipeline이 아니라 Declarative Pipeline을 표준으로 다룬다. ( )

**6.** 오늘(1차시) 수업에서는 개인 VM에 Jenkinsfile을 실제로 적용하는 실습을 진행한다. ( )

## 단답형 문제 (7~10번)

**7.** Jenkinsfile에서 전체를 감싸는 최상위 블록의 이름은 무엇인가요?

**8.** `Checkout → Build → Push → Deploy`처럼 파이프라인을 여러 단계로 나눈 것을 무엇이라고
부르나요?

**9.** Jenkins가 기본으로 제공해서 파이프라인 안에서 바로 쓸 수 있는 변수의 예시를 하나 쓰세요.

**10.** Jenkinsfile은 보통 어디에 함께 저장하나요?

---

## 정답 및 해설

| 번호 | 정답 | 해설 |
|---|---|---|
| 1 | O | Jenkinsfile로 빌드 파이프라인을 코드화하면 Git으로 버전관리·리뷰·재사용이 가능해진다. |
| 2 | X | `any`는 "아무 에이전트나 써도 된다"는 뜻이다. 특정 서버로 고정하는 것이 아니다. |
| 3 | O | stage로 나누면 각 단계의 성공/실패를 Jenkins UI에서 시각적으로 확인할 수 있어, 실패 시 어느 단계인지 한눈에 알 수 있다. |
| 4 | X | `withCredentials`는 민감정보를 코드에 **그대로 노출하지 않고** 안전하게 사용하기 위한 방법이다. 평문으로 적으면 GitHub에 그대로 노출되므로 반드시 이 방식을 써야 한다. |
| 5 | O | Declarative Pipeline이 더 읽기 쉽고 표준적이라 이 과목에서는 이것만 다룬다. |
| 6 | X | 오늘은 문법 이해에 집중하고, VM에 실제로 적용하는 실습은 다음 2차시부터 진행한다. |
| 7 | `pipeline` | `pipeline { }`이 전체를 감싸는 최상위 블록이다. |
| 8 | stage (stages) | `stages { }` 안에 여러 `stage("이름") { steps { ... } }`를 나열해 단계를 나눈다. |
| 9 | `$BUILD_NUMBER` | Jenkins가 기본 제공하는 환경변수의 예시다. |
| 10 | 프로젝트의 GitHub 저장소 안 | 보통 저장소 안에 `Jenkinsfile`이라는 이름으로 함께 저장하며, Jenkins가 이를 직접 읽어오는 방식은 3차시에서 다룬다. |
