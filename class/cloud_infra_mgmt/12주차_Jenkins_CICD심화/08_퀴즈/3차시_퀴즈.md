# 12주차 3차시 — Poll SCM 자동 빌드 연동 퀴즈 (OX·단답형 10문항)

- 범위: 12주차 3차시(Webhook vs Poll SCM, Poll SCM 설정 및 자동 빌드 확인)
- 형식: OX 6문항 + 단답형 4문항
- 용도: LMS 자동채점 퀴즈. 수업 중 함께 풀고 바로 정답·해설을 확인합니다.

---

## OX 문제 (1~6번)

**1.** Webhook 방식은 GitHub이 push를 감지하면 즉시 Jenkins 서버로 직접 알림을 보내는 방식이다.
( )

**2.** 우리 실습 환경의 개인 VM은 공인 주소를 가지고 있어 Webhook 방식을 바로 사용할 수 있다. ( )

**3.** Poll SCM은 Jenkins가 주기적으로 GitHub에 변경사항이 있는지 스스로 물어보는 방식이다. ( )

**4.** Poll SCM을 쓰려면 학생 VM이 외부(GitHub)에서 접근 가능해야 한다. ( )

**5.** Schedule에 `* * * * *`를 입력하면 매 1분마다 변경사항을 확인한다. ( )

**6.** Poll SCM 설정 후 코드 변경이 없어도 정해진 주기마다 새 빌드가 항상 실행된다. ( )

## 단답형 문제 (7~10번)

**7.** Poll SCM 설정은 Job 설정 화면의 어느 섹션에서 체크하나요?

**8.** cron 표현식 `* * * * *`가 의미하는 확인 주기를 쓰세요.

**9.** git push가 실제로 완료됐는지, 최신 커밋이 반영됐는지 로컬에서 확인할 때 쓰는 명령어는
무엇인가요?

**10.** 오늘(3차시)은 12주차의 마지막 시간입니다. 실습 후 무엇을 종합해서 제출해야 하나요?

---

## 정답 및 해설

| 번호 | 정답 | 해설 |
|---|---|---|
| 1 | O | Webhook은 GitHub이 push를 감지해 Jenkins 서버로 직접 HTTP 알림을 보내는 실시간에 가까운 방식이다. |
| 2 | X | 개인 VM은 가정용 공유기 NAT 뒤에 있어 공인 주소가 없으므로, Webhook 방식은 애초에 동작할 수 없다. |
| 3 | O | Poll SCM은 GitHub이 알려주는 게 아니라, Jenkins가 스스로 GitHub에 "변경 사항 있어?"라고 물어보러 가는 방식이다. |
| 4 | X | Poll SCM은 Jenkins가 능동적으로 나가서 확인하는 구조라서, 학생 VM이 NAT 뒤에 있어도(외부에서 접근 불가능해도) 아무 문제가 없다. |
| 5 | O | `* * * * *`는 매 1분마다 GitHub에 변경사항을 확인하라는 cron 표현식이다. |
| 6 | X | 변경 사항이 없으면 빌드는 실행되지 않는다. 변경이 있을 때만 자동으로 빌드가 시작된다. |
| 7 | Build Triggers | Job 설정 화면의 Build Triggers 섹션에서 'Poll SCM'을 체크한다. |
| 8 | 매 1분마다 | 다섯 자리 모두 `*`이므로 1분마다 확인한다는 뜻이다. |
| 9 | `git log` | 최신 커밋이 반영되었는지 `git log`로 확인할 수 있다. 자동 빌드가 안 될 때 점검할 항목 중 하나다. |
| 10 | 1차시(문법)·2차시(Jenkinsfile 작성)·3차시(Poll SCM) 실습 결과 | 12주차 마지막 시간이므로 1~3차시 실습 결과를 종합해서 LMS 과제 게시판에 제출한다. |
