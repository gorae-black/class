# 12주차 1차시 실습가이드

## 개요
오늘은 Jenkinsfile을 이용한 **Declarative Pipeline** 문법(`pipeline`, `agent`, `stages`, `stage`,
`steps`, `environment`, `withCredentials`)을 개념으로 이해하는 시간입니다. 실제 VM에 Jenkinsfile을
적용하는 실습은 **다음 2차시부터** 진행되며, 오늘은 별도의 VM 실습(제출용 실습)이 없습니다.

## VM 실습
**오늘은 개인 VM에 Jenkinsfile을 적용하는 실습이 없습니다.** 11주차에 만든 `hello-jenkins` Job은
**지우지 말고 그대로 남겨두세요.** 2차시부터 새로운 Pipeline Job(`myflask-pipeline`)을 만들어
진행합니다.

다음 시간 실습을 대비해, 오늘 배운 뼈대 구조를 참고해서 스스로 이해를 점검해보고 싶다면 아래
내용을 노트나 텍스트 파일에 정리해보세요. (제출 대상 아님, Jenkins에 연결하거나 실행할 필요
없습니다.)

- 파이프라인 전체를 감싸는 최상위 블록: `pipeline { }`
- 어떤 에이전트(서버)에서 실행할지 지정: `agent any` (`any`는 아무 에이전트나 써도 된다는 뜻)
- 여러 단계를 순서대로 나열하는 블록: `stages { }`, 그 안에 `stage("이름") { steps { ... } }`
- 기본 뼈대 예시:

```groovy
pipeline {
  agent any
  stages {
    stage("Build") {
      steps { ... }
    }
  }
}
```

- 파이프라인을 여러 `stage`(예: `Checkout` → `Build` → `Push` → `Deploy`)로 나누면, Jenkins UI에서
  각 단계의 성공/실패를 시각적으로 확인할 수 있다는 점을 다시 떠올려보세요.
- `environment { }` 블록으로 환경변수를 선언하고, `$BUILD_NUMBER`처럼 Jenkins가 기본 제공하는
  변수도 쓸 수 있다는 점, `withCredentials { }`로 Docker Hub 비밀번호 같은 민감정보를 코드에 그대로
  노출하지 않고 안전하게 다룬다는 점을 정리해보세요.
