# 12주차 3차시 실습가이드

## 개요
지난 2차시에서 Build Now로 수동 빌드에 성공했습니다. 오늘은 매번 손으로 버튼을 누르지 않고, GitHub에
`git push`만 하면 자동으로 빌드가 시작되도록 **Poll SCM**을 설정합니다. 우리 개인 VM은 가정용
공유기 NAT 뒤에 있어 공인 주소가 없기 때문에, GitHub이 직접 알려주는 **Webhook** 방식은 쓸 수
없습니다. 대신 Jenkins가 스스로 GitHub에 변경 여부를 물어보러 가는 **Poll SCM** 방식을 사용합니다.
오늘은 12주차의 마지막 시간이므로, 실습 후 1~3차시 과제를 종합해서 제출합니다.

## VM 실습

### 1. Poll SCM 설정
1. 개인 VM Jenkins에서 2차시에 만든 **`myflask-pipeline`** Job 설정 화면으로 들어갑니다.
2. **Build Triggers** 섹션을 찾아 **Poll SCM**을 체크합니다.
3. Schedule 입력란에 cron 형식으로 `* * * * *`를 입력합니다 — '매 1분마다 확인한다'는 뜻입니다.
4. 저장합니다.

### 2. 자동 빌드 트리거 확인 (본인 GitHub 저장소에 직접 push)
1. 저장 직후 아무 변경 없이 잠시 기다려보면 빌드가 실행되지 않는 것을 확인합니다 (정상입니다 —
   변경 사항이 없으니까요).
2. 로컬에서 `cloud-lab` 저장소의 `app.py`를 한 줄 수정합니다.
3. 변경사항을 본인의 GitHub 저장소에 실제로 **commit 후 push**합니다.
4. 수 초에서 1분 이내에 Jenkins가 변경을 감지해 자동으로 빌드가 시작되는지 **Build History**에서
   직접 관찰합니다. 자동으로 트리거된 빌드는 'SCM 변경 감지'로 실행된 빌드로 표시됩니다.

### 3. 안 될 때 확인할 것
1분이 지나도 자동 빌드가 트리거되지 않으면 아래를 순서대로 확인하세요.
- `git push`가 실제로 완료되었는지 (`git log`로 최신 커밋이 반영되었는지 확인)
- Poll SCM의 Schedule 문자열이 정확히 `* * * * *`인지
- Jenkinsfile의 `git url`이 본인 저장소 주소와 일치하는지

## 제출 안내
- `myflask-pipeline` Job에 Poll SCM(`* * * * *`)이 설정된 화면 캡처
- `app.py` 수정 후 `git push`한 뒤, 1분 이내에 자동으로 빌드가 시작된 것을 확인한 **Build History**
  화면 캡처
- 오늘이 12주차 마지막 시간이므로, **1차시(문법)·2차시(Jenkinsfile 작성)·3차시(Poll SCM)** 실습
  결과를 모두 종합하여 LMS 과제 게시판에 제출합니다.
