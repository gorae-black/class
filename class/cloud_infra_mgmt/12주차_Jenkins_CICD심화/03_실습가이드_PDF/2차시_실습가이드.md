# 12주차 2차시 실습가이드

## 개요
지난 1차시에서 배운 Declarative Pipeline 문법을 이용해, 실제로 **Checkout + Build** 단계를 가진
Jenkinsfile을 작성하고, 이를 개인 VM의 Jenkins에 **Pipeline Job**으로 등록해 **Build Now**로
수동 실행까지 해봅니다. 핵심 실습 소요시간은 약 14분입니다.

## VM 실습

### 1. 3주차 cloud-lab 저장소 확인
오늘은 완전히 새로운 프로젝트를 만들지 않고, **3주차에 GitHub에 올렸던 `cloud-lab` 저장소**(`app.py`,
`Dockerfile` 포함)를 다시 활용합니다. 본인 GitHub 계정에서 이 저장소가 남아있는지 먼저 확인하세요.
만약 삭제했다면, 3주차 자료를 참고해 `app.py`, `Dockerfile`을 다시 만들고 저장소에 push한 뒤
진행하세요.

### 2. Jenkinsfile 작성
아래 내용을 그대로 작성하되, `{id}` 자리에는 **본인의 GitHub 아이디**를 넣습니다.

```groovy
pipeline {
  agent any
  stages {
    stage("Checkout") {
      steps { git url: "https://github.com/{id}/cloud-lab.git", branch: "main" }
    }
    stage("Build") {
      steps { sh "docker build -t myflask:test ." }
    }
  }
}
```

- `Checkout` stage는 `git url: "..."` 스텝으로 GitHub 저장소를 가져옵니다.
- `Build` stage는 `sh` 스텝으로 셸 명령어(`docker build`)를 실행합니다. 3주차에 터미널에서 직접
  쳤던 것과 같은 `docker build` 명령을 이제 Jenkins가 대신 실행해줍니다.
- 저장소가 **Private**로 설정되어 있으면 Jenkins가 접근하지 못해 Checkout 단계에서 인증 오류가
  납니다. GitHub 저장소 설정에서 **Public**으로 되어 있는지 확인하세요.

### 3. Pipeline Job 생성 (Freestyle 아님, 주의!)
1. VM Jenkins에서 **New Item**을 클릭합니다.
2. 이번엔 **Pipeline** 타입을 선택합니다. 11주차의 **Freestyle project**와는 다른 타입이니 꼭
   확인하세요 — 실수로 Freestyle을 선택하면 Pipeline script 입력란 자체가 나오지 않습니다.
3. Job 이름을 입력합니다 (예: `myflask-pipeline`).
4. 아래로 스크롤해 **Pipeline** 섹션을 찾고, **Pipeline script** 텍스트 칸에 위에서 작성한
   Jenkinsfile 내용을 그대로 붙여넣습니다.
5. 저장합니다.

### 4. Build Now 실행 및 결과 확인
1. **Build Now**를 클릭합니다.
2. 화면에 나타나는 **Stage View**에서 `Checkout`과 `Build` 단계가 순서대로 진행되고, 각 단계가
   **초록색**(성공)으로 표시되는지 확인합니다. 빨간색이면 그 단계에서 오류가 난 것입니다.
3. **Console Output**을 열어 `git clone` 로그와 `docker build` 로그가 순서대로 출력되었는지
   확인합니다.
4. 빌드가 끝난 후 VM 터미널에서 `docker images`를 실행해, `myflask:test`라는 이미지가 실제로
   만들어졌는지 확인합니다.

## 제출 안내
- Build Now 실행 후 **Stage View** 화면 캡처
- **Console Output** 화면 캡처
- `docker images` 실행 결과에서 `myflask:test` 이미지가 생성된 것을 확인한 화면 캡처

이번 차시의 제출물은 12주차 3차시(마지막 시간)에 1~3차시 실습 결과와 함께 종합 제출합니다.
