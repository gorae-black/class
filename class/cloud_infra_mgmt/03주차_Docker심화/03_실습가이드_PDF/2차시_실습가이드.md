# 3주차 2차시 실습가이드

## 개요

지난 1차시에서 `Dockerfile` 문법을 배웠습니다. 오늘은 그걸 실제로 써먹어 볼 차례입니다. 여러분이
직접 작성한 아주 간단한 Python Flask 앱을 `Dockerfile`로 빌드해서 이미지로 만들어봅니다. 이
코드를 외울 필요는 전혀 없습니다 — 오늘 목표는 파이썬 문법을 익히는 게 아니라, "내가 만든 앱을
Dockerfile로 이미지화하는 전체 흐름"을 경험하는 것입니다. 소요시간은 개념 설명(계정 준비 포함)
25분 + Killercoda 실습 15분 + VM 과제 안내 5분 + 결과 제출 5분입니다.

**이 실습은 이번 주차 정식 VM 과제입니다.** Killercoda에서 먼저 연습해보고, 이후 개인 로컬
VM에서 동일하게 실행한 결과를 GitHub 저장소 push와 함께 제출해야 합니다. (Docker Hub push는
다음 3차시의 선택 심화 과제이니, 오늘은 로컬 build·run·curl 확인까지만 하면 됩니다.)

## Part A. Killercoda 실습

LMS > 3주차 > 2차시 > `05_Killercoda_링크`의 URL로 접속한 뒤 아래 순서대로 진행하세요.

> 이 세션은 **60분 제한**이 있습니다. 실습 중 시간이 종료되어도 당황하지 마세요 — 만약 중간에
> 끊기면 LMS의 링크로 다시 접속해 이어서 진행하면 됩니다.

**[1] Flask 앱 작성하기**

먼저 작업할 폴더를 만들고 이동합니다.

```
mkdir ~/myflask && cd ~/myflask
```

Flask는 파이썬으로 웹 서버를 아주 간단하게 만들 수 있게 해주는 라이브러리입니다. `/`로 접속하면
`Hello, Cloud!`를 응답하는 앱을 만듭니다.

```
cat <<'EOF' > app.py
from flask import Flask

app = Flask(__name__)

@app.route('/')
def hello():
    return 'Hello, Cloud!'

if __name__ == '__main__':
    app.run(host='0.0.0.0', port=5000)
EOF
```

별다른 출력 없이 조용히 파일이 만들어집니다. `cat app.py`로 내용을 확인해보세요.

```
cat app.py
```

`app.py` 파일이 잘 만들어졌는지 확인했다면, 이제 이 앱을 이미지로 만들 `Dockerfile`을 작성할
차례입니다.

**[2] Dockerfile 작성하기**

지난 1차시에서 배운 명령어들을 이 Flask 앱에 그대로 적용해서 `Dockerfile`을 작성합니다.

`FROM python:3.11-slim`으로 파이썬이 설치된 기반 이미지를 가져오고, `WORKDIR /app`으로 작업
폴더를 정합니다. `COPY app.py .`로 방금 만든 파일을 이미지 안에 넣고, `RUN pip install flask`로
Flask 라이브러리를 설치합니다. `EXPOSE 5000`으로 5000번 포트를 쓴다고 알려주고, 마지막
`CMD ["python", "app.py"]`로 컨테이너가 시작될 때 이 앱을 실행하도록 합니다.

```
cat <<'EOF' > Dockerfile
FROM python:3.11-slim
WORKDIR /app
COPY app.py .
RUN pip install flask
EXPOSE 5000
CMD ["python", "app.py"]
EOF
```

`cat Dockerfile`로 확인합니다.

```
cat Dockerfile
```

실행 결과 예시:

```
FROM python:3.11-slim
WORKDIR /app
COPY app.py .
RUN pip install flask
EXPOSE 5000
CMD ["python", "app.py"]
```

`Dockerfile`의 여섯 줄이 그대로 보이면 정상입니다.

**[3] 이미지 빌드하기**

`app.py`와 `Dockerfile`이 준비됐으니, `docker build -t myflask:v1 .`으로 빌드합니다.

```
docker build -t myflask:v1 .
```

실행 결과 예시:

```
[+] Building 12.8s (9/9) FINISHED
 => [1/4] FROM docker.io/library/python:3.11-slim
 => [2/4] WORKDIR /app
 => [3/4] COPY app.py .
 => [4/4] RUN pip install flask
 => exporting to image
 => => naming to docker.io/library/myflask:v1
```

`Successfully tagged` 또는 `naming to ... myflask:v1` 문구가 마지막에 보이면 빌드 성공입니다.
`docker images`로 이미지 목록에 `myflask`가 생겼는지도 확인해보세요.

```
docker images
```

`pip install flask` 과정에서 시간이 조금 걸릴 수 있습니다 — 파이썬 기반 이미지를 내려받고 그
위에 Flask 라이브러리까지 설치하기 때문입니다.

**[4] 컨테이너 실행하고 curl로 확인하기**

이미지를 컨테이너로 실행하고, `curl`로 실제 응답이 오는지 확인합니다. `-p 5000:5000`은
컨테이너의 5000번 포트를 이 터미널의 5000번 포트로 연결합니다.

```
docker run -d -p 5000:5000 myflask:v1
```

컨테이너가 뜬 뒤 `curl`로 `/`에 접속해봅니다.

```
curl localhost:5000
```

실행 결과 예시:

```
Hello, Cloud!
```

`Hello, Cloud!`가 그대로 출력되면 성공입니다. `docker ps`로도 컨테이너가 `Up` 상태인지 다시 한
번 확인해보세요.

```
docker ps
```

여러분이 직접 작성한 코드가 이미지가 되고, 그 이미지로 컨테이너가 실행되어 실제로 응답을 준다는
전체 흐름을 오늘 처음부터 끝까지 경험한 것입니다. 여기까지가 오늘의 Killercoda 실습입니다.

## Part B. 개인 VM 실습 (★ 필수 제출)

개인 로컬 VM(`cloud-lab`)에서 위와 동일한 흐름을 그대로 진행합니다.

1. VM에 접속합니다.

   ```
   multipass shell cloud-lab
   ```

2. Killercoda에서 한 것과 동일하게 작업 폴더를 만들고 `app.py`, `Dockerfile`을 작성합니다
   (위 Part A [1], [2]의 내용을 그대로 VM에서 반복합니다).

3. 이미지를 빌드하고, 컨테이너로 실행하고, `curl`로 확인합니다.

   ```
   docker build -t myflask:v1 .
   docker run -d -p 5000:5000 myflask:v1
   curl localhost:5000
   ```

4. `Hello, Cloud!`가 출력되는 화면을 캡처해둡니다. **이 화면 캡처가 필수 제출물입니다.**

5. `app.py`와 `Dockerfile` 두 파일을 1차시에 만들어둔 GitHub 저장소(`cloud-lab`)에
   올립니다.

   ```
   git add app.py Dockerfile
   git commit -m "3주차 2차시: Flask 앱 Dockerfile 빌드"
   git push
   ```

   `git push`가 인증 오류로 실패한다면, GitHub는 2021년부터 비밀번호 대신 Personal Access
   Token(PAT) 또는 SSH 키를 요구합니다. GitHub Settings → Developer settings → Personal access
   tokens에서 토큰을 발급받아, 비밀번호 입력란에 그 토큰을 대신 붙여넣으면 됩니다.

6. GitHub 저장소가 **Public**으로 설정되어 있는지 확인합니다. Private이면 채점자가 확인할 수
   없습니다.

**오늘 필수 제출물은 여기까지입니다.** Docker Hub에 이미지를 올리는 것은 다음 3차시의 선택
심화 과제이니, 오늘은 부담 갖지 않으셔도 됩니다.

## 제출 안내

- 제출 대상: 로컬 VM에서 `docker build` → `docker run` → `curl localhost:5000` 실행 결과
  (`Hello, Cloud!` 출력) 캡처, GitHub 저장소 링크(`https://github.com/{본인아이디}/cloud-lab`)
- 제출 위치: LMS 과제 게시판 (자세한 양식은 `10_과제제출/3주차_과제제출양식.md` 참고)
- GitHub 저장소는 반드시 Public으로 설정되어 있어야 합니다.
- Docker Hub push는 3차시의 선택 심화 과제이며, 오늘 제출 범위에는 포함되지 않습니다.
