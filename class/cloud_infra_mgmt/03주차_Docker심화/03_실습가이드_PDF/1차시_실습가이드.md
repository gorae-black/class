# 3주차 1차시 실습가이드

## 개요

지금까지 2주 동안은 nginx처럼 다른 사람이 이미 만들어 둔 이미지만 가져다 썼습니다. 오늘부터는
드디어 여러분만의 이미지를 직접 만드는 방법, `Dockerfile`을 배웁니다. `Dockerfile`은 "이런
순서로 이미지를 만들어라"라고 적어두는 설계도(레시피)이고, 이 레시피를 `docker build` 명령으로
실제 이미지로 바꿉니다. 소요시간은 Killercoda 실습 15분 + 계정 준비 안내 5분입니다.

## Part A. Killercoda 실습

LMS > 3주차 > 1차시 > `05_Killercoda_링크`의 URL로 접속한 뒤 아래 순서대로 진행하세요.

> 이 세션은 **60분 제한**이 있습니다. 실습 중 시간이 종료되어도 당황하지 마세요 — 오늘 실습은
> 짧게 끝나므로 문제 없지만, 만약 중간에 끊기면 LMS의 링크로 다시 접속해 이어서 진행하면 됩니다.

**[1] Node.js 앱 파일 준비하기**

오늘 이미지로 만들어볼 아주 간단한 Node.js 앱 파일을 먼저 준비합니다. 작업할 폴더를 만들고
이동합니다.

```
mkdir ~/mynode && cd ~/mynode
```

앱 파일 `app.js`를 만듭니다. 간단한 웹 서버 하나를 띄우는 코드입니다.

```
cat <<'EOF' > app.js
const http = require('http');
const port = 3000;

const server = http.createServer((req, res) => {
  res.statusCode = 200;
  res.setHeader('Content-Type', 'text/plain');
  res.end('Hello from Node.js in Docker!\n');
});

server.listen(port, () => {
  console.log(`Server running at http://localhost:${port}/`);
});
EOF
```

`package.json`도 함께 만듭니다.

```
cat <<'EOF' > package.json
{
  "name": "mynode",
  "version": "1.0.0",
  "main": "app.js",
  "scripts": {
    "start": "node app.js"
  }
}
EOF
```

두 명령 모두 별다른 출력 없이 조용히 파일을 만듭니다. `ls`로 파일이 잘 생겼는지 확인하세요.

```
ls
```

실행 결과 예시:

```
app.js  package.json
```

`app.js`와 `package.json` 두 파일이 보이면 정상입니다.

**[2] 빈칸 Dockerfile 완성하기**

오늘 강의에서 본 것처럼, 아래는 일부(`FROM` / `COPY` / `RUN` / `CMD`)가 빈칸으로 되어 있는
`Dockerfile`입니다.

```
FROM ____
WORKDIR /app
COPY ____
RUN ____
CMD ____
```

각 빈칸에 무엇이 들어가야 할지 생각해봅니다.

- `FROM`: Node.js가 설치되어 있는 기반 이미지
- `COPY`: 방금 만든 `package.json`과 `app.js`를 이미지 안으로 복사하는 명령
- `RUN`: 이미지를 만드는 동안 패키지를 설치하는 명령
- `CMD`: 컨테이너가 시작될 때 앱을 실행하는 명령

아래 명령으로 빈칸을 채운 완성된 `Dockerfile`을 작성합니다.

```
cat <<'EOF' > Dockerfile
FROM node:18-slim
WORKDIR /app
COPY package.json .
RUN npm install
COPY app.js .
CMD ["node", "app.js"]
EOF
```

`cat Dockerfile`로 확인해서 `FROM`, `COPY`, `RUN`, `CMD` 네 줄 모두 빈칸 없이 채워져 있는지
확인하세요.

```
cat Dockerfile
```

실행 결과 예시:

```
FROM node:18-slim
WORKDIR /app
COPY package.json .
RUN npm install
COPY app.js .
CMD ["node", "app.js"]
```

**[3] 이미지 빌드하기 — `docker build`**

완성한 `Dockerfile`을 실제 이미지로 만들어봅니다. `docker build -t {이름}:{태그} .` 명령은
현재 폴더(`.`)의 `Dockerfile`을 읽어서 한 줄씩 순서대로 실행하며 이미지를 만듭니다.

```
docker build -t mynode:v1 .
```

실행 결과 예시:

```
[+] Building 4.2s (10/10) FINISHED
 => [1/4] FROM docker.io/library/node:18-slim
 => [2/4] WORKDIR /app
 => [3/4] COPY package.json .
 => [4/5] RUN npm install
 => [5/5] COPY app.js .
 => exporting to image
 => => naming to docker.io/library/mynode:v1
```

마지막 줄에 `mynode:v1`으로 이미지 이름이 지정된 것이 보이면 빌드 성공입니다. `docker images`로도
확인할 수 있습니다.

```
docker images
```

목록에 `mynode` 이미지가 있으면, `Dockerfile`의 레시피대로 이미지가 잘 만들어진 것입니다.

**[4] 컨테이너로 실행하고 확인하기**

마지막으로 방금 만든 이미지를 컨테이너로 실행해서 정상 동작하는지 확인합니다. `-p 3000:3000`은
컨테이너의 3000번 포트를 이 터미널의 3000번 포트로 연결하는 옵션입니다.

```
docker run -d --name mynode-app -p 3000:3000 mynode:v1
```

`docker ps`로 컨테이너가 정상적으로 떠 있는지 확인합니다.

```
docker ps
```

실행 결과 예시:

```
CONTAINER ID   IMAGE         COMMAND                  STATUS         PORTS                    NAMES
a1b2c3d4e5f6   mynode:v1     "docker-entrypoint.s…"   Up 5 seconds   0.0.0.0:3000->3000/tcp   mynode-app
```

`docker logs`로 앱이 실제로 정상 실행됐는지도 확인해봅니다.

```
docker logs mynode-app
```

실행 결과 예시:

```
Server running at http://localhost:3000/
```

STATUS가 `Up ...`이고, 로그에 "Server running..." 메시지가 보이면 빈칸 Dockerfile을 제대로
완성해서 이미지를 만들고 실행까지 성공한 것입니다. 여기까지가 오늘의 Killercoda 실습입니다.

## Part B. 계정 준비 — GitHub·Docker Hub 가입 (다음 차시 전 필수)

이번 차시는 별도의 결과 캡처 제출이 없습니다. 대신 **다음 2차시부터는 GitHub 계정과 Docker Hub
계정이 반드시 필요**합니다. 아직 계정이 없다면 다음 시간 전까지 아래 순서대로 미리 가입해두세요.
0~2주차에 걸쳐 이미 여러 번 예고된 내용이니, 오늘이 진짜 필요해지는 마지막 리마인드입니다.

**[1] GitHub 계정 가입하기**

GitHub는 코드를 저장하고 관리하는 서비스입니다. 이미 계정이 있으면 이 단계는 건너뛰어도 됩니다.

1. 웹 브라우저로 https://github.com 에 접속합니다.
2. 우측 상단 `Sign up` 버튼을 누릅니다.
3. 이메일 · 비밀번호 · 사용자명(username)을 입력해서 계정을 만듭니다.
4. 가입 시 발송되는 이메일 인증까지 완료합니다.
5. 로그인 상태에서 우측 상단 `+` 버튼을 눌러 `New repository`로 저장소를 하나 만들어둡니다.
   이름은 예를 들어 `cloud-lab`처럼 자유롭게 지으면 됩니다. 다음 2차시부터 이 저장소에 실습
   결과물을 올리게 됩니다.

**[2] Docker Hub 계정 가입하기**

Docker Hub는 우리가 만든 이미지를 저장하고 공유하는 저장소입니다.

1. 웹 브라우저로 https://hub.docker.com 에 접속합니다.
2. `Sign Up`을 누릅니다.
3. 이메일 · 비밀번호 · Docker ID(사용자명)를 입력해서 계정을 만듭니다.
4. **이 Docker ID를 꼭 기억해두세요** — 3차시 실습에서 `{여러분의dockerhub_id}` 자리에 이
   값을 넣게 됩니다.

계정 가입 방법은 다음 2차시 시작할 때 교수님이 화면 공유로 단계별로 다시 안내해주시니, 지금 당장
완벽하게 하지 못했더라도 걱정하지 마세요. 다만 이메일 인증 메일이 스팸함에 들어가는 경우가 많으니,
가입 후에는 스팸함도 함께 확인해두면 좋습니다.
