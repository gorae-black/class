# 3주차 3차시 — 이미지 최적화와 Docker Hub 배포 퀴즈 (OX·단답형 8문항)

- 범위: 3주차 3차시(레이어 캐싱, .dockerignore, Docker Hub push)
- 형식: OX 5문항 + 단답형 3문항
- 용도: LMS 자동채점 퀴즈. 수업 중 함께 풀고 바로 정답·해설을 확인합니다.

---

## OX 문제 (1~5번)

**1.** `Dockerfile`을 다시 빌드할 때, 바뀌지 않은 앞부분의 레이어는 새로 만들지 않고 캐시를
재사용한다. ( )

**2.** `Dockerfile` 중간의 한 줄이 바뀌면, 그 위에 있는 레이어까지 모두 다시 만들어야 한다. ( )

**3.** 빌드 속도를 높이려면 자주 바뀌는 코드(`COPY`)는 위쪽에, 자주 바뀌지 않는 라이브러리
설치(`RUN`)는 아래쪽에 배치하는 것이 좋다. ( )

**4.** `.dockerignore`는 `.gitignore`와 비슷하게, 이미지 빌드에 포함시키지 않을 파일이나
폴더를 지정하는 파일이다. ( )

**5.** 이번 차시에서 완성한 이미지를 Docker Hub에 push하는 것은 필수 제출물이다. ( )

## 단답형 문제 (6~8번)

**6.** `docker build` 실행 결과에서, 이전 빌드의 레이어를 그대로 재사용했을 때 해당 레이어
앞에 붙는 표시는 무엇인가요?

**7.** 캐시를 완전히 무시하고 처음부터 다시 빌드하고 싶을 때 `docker build`에 추가하는
옵션은 무엇인가요?

**8.** 레이어 캐싱이 빌드 속도를 높이는 이유를 한 문장으로 설명하세요.

---

## 정답 및 해설

| 번호 | 정답 | 해설 |
|---|---|---|
| 1 | O | 다시 빌드할 때 바뀌지 않은 앞부분의 레이어는 새로 만들지 않고 그대로 재사용한다(캐시). |
| 2 | X | 반대다. 중간의 한 줄이 바뀌면 그 **아래**에 있는 레이어를 전부 다시 만들어야 한다. 위쪽 레이어는 영향받지 않는다. |
| 3 | X | 반대다. 자주 안 바뀌는 것(`RUN` 라이브러리 설치)을 위쪽에, 자주 바뀌는 것(`COPY` 코드)을 아래쪽에 두어야 캐시 적중률이 높아져 빌드가 빨라진다. |
| 4 | O | `.dockerignore`는 `__pycache__/`, `.git/`, `*.log`처럼 이미지에 넣을 필요 없는 파일·폴더를 빌드에서 제외한다. |
| 5 | X | Docker Hub push는 선택 심화 과제이며, 필수 제출물은 레이어 순서 변경 전/후 빌드 시간 비교와 `.dockerignore` 적용 확인이다. |
| 6 | `CACHED` | 캐시가 재사용된 레이어 앞에는 `CACHED`라는 문구가 표시된다. |
| 7 | `--no-cache` | `docker build --no-cache`를 쓰면 캐시를 무시하고 모든 레이어를 처음부터 새로 만든다. |
| 8 | (예시) 자주 안 바뀌는 것을 위에 두면 캐시가 재사용되고, 바뀐 부분 아래 레이어만 다시 만들면 되기 때문이다. | 핵심은 "변경이 적은 명령을 위에 배치해 캐시 재사용 범위를 넓힌다"는 취지 — 채점 시 이 취지가 담기면 정답 처리 |
