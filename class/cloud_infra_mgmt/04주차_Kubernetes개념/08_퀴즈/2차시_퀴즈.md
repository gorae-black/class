# 4주차 2차시 — Pod 개념·kubectl 기본 명령어 퀴즈 (OX·단답형 8문항)

- 범위: 4주차 2차시(Pod — K8s의 가장 작은 단위, kubectl로 Pod 다루기)
- 형식: OX 5문항 + 단답형 3문항
- 용도: LMS 자동채점 퀴즈. 수업 중 함께 풀고 바로 정답·해설을 확인합니다.

---

## OX 문제 (1~5번)

**1.** Kubernetes는 컨테이너를 직접 다루지 않고, Pod라는 단위로 한 번 감싸서 다룬다. ( )

**2.** 하나의 Pod 안에는 컨테이너가 정확히 1개만 들어갈 수 있으며, 2개 이상은 넣을 수 없다. ( )

**3.** 같은 Pod 안에 있는 컨테이너들은 네트워크(IP 주소)와 저장 공간을 서로 공유한다. ( )

**4.** `kubectl run`으로 만든 단독 Pod가 죽으면, K8s가 자동으로 새 Pod를 만들어 다시 살려준다. ( )

**5.** `kubectl describe pod`의 결과에 있는 Events 섹션에서 Pod가 어떤 순서로 생성되었는지(예:
Scheduled → Pulled → Created → Started) 확인할 수 있다. ( )

## 단답형 문제 (6~8번)

**6.** Pod 하나를 즉석에서 실행할 때 사용하는 명령어의 기본 형식을 쓰세요. (예: `kubectl run
{이름} --image={이미지}`처럼 형식으로 답하세요.)

**7.** 지금 클러스터에 떠 있는 Pod 목록과 상태(Running 등)를 확인하는 명령어는 무엇인가요?

**8.** Pod가 출력한 로그를 확인하는 명령어는 무엇인가요?

---

## 정답 및 해설

| 번호 | 정답 | 해설 |
|---|---|---|
| 1 | O | K8s는 컨테이너를 Pod라는 단위로 감싸서 다룬다. |
| 2 | X | 보통은 1개가 들어가지만, 필요하면 여러 개의 컨테이너를 하나의 Pod에 넣을 수도 있다(예: 앱 컨테이너 + 사이드카 컨테이너). |
| 3 | O | 같은 Pod 안의 컨테이너들은 네트워크와 저장 공간을 서로 공유한다. |
| 4 | X | `kubectl run`으로 만든 단독 Pod는 죽으면 그걸로 끝이다. 자동으로 다시 살아나게 하려면 Deployment로 관리해야 한다(3차시에서 학습). |
| 5 | O | Events 섹션에서 Scheduled → Pulled → Created → Started 순서로 잘 진행됐는지 확인할 수 있다. |
| 6 | `kubectl run {이름} --image={이미지}` | Docker의 `docker run`과 거의 같은 구조다. |
| 7 | `kubectl get pods` | 현재 떠 있는 Pod들의 이름과 READY·STATUS·RESTARTS·AGE를 보여준다. |
| 8 | `kubectl logs {이름}` | 해당 Pod(컨테이너)가 출력한 로그를 확인할 수 있다. |
