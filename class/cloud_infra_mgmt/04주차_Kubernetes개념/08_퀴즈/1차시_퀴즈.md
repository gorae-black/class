# 4주차 1차시 — Kubernetes 개요·아키텍처 퀴즈 (OX·단답형 8문항)

- 범위: 4주차 1차시(Kubernetes, 왜 필요한가 — 오케스트레이션의 필요성, 클러스터 아키텍처 개관)
- 형식: OX 5문항 + 단답형 3문항
- 용도: LMS 자동채점 퀴즈. 수업 중 함께 풀고 바로 정답·해설을 확인합니다.

---

## OX 문제 (1~5번)

**1.** Kubernetes(K8s)는 여러 대의 서버(노드)에 걸쳐서 컨테이너를 자동으로 배포하고 관리해주는
오케스트레이션 도구이다. ( )

**2.** K8s에게 '몇 개가 항상 떠 있어야 한다'고 선언하면, K8s는 그 선언과 무관하게 사람이 매번 직접
개수를 맞춰야 한다. ( )

**3.** K8s 클러스터에서 Control Plane은 클러스터 전체를 지휘하는 '두뇌'이고, Worker Node는 컨테이너
(Pod)가 실제로 돌아가는 '일꾼'이다. ( )

**4.** K8s 클러스터는 반드시 노드가 2대 이상이어야만 성립하며, 노드 1대로는 클러스터라고 부를 수
없다. ( )

**5.** 우리가 사용하는 minikube는 클러스터 전체를 노드 여러 대에 나누어 구성한 것이다. ( )

## 단답형 문제 (6~8번)

**6.** Docker와 Kubernetes의 관계를 한 문장으로 설명하세요.

**7.** Pod(또는 컨테이너)가 죽었을 때 K8s가 자동으로 다시 띄워주는 성질을 무엇이라고 부르나요?

**8.** 클러스터에 어떤 노드들이 있는지 확인할 때 사용하는 kubectl 명령어는 무엇인가요?

---

## 정답 및 해설

| 번호 | 정답 | 해설 |
|---|---|---|
| 1 | O | K8s는 여러 노드에 걸쳐 컨테이너를 자동으로 배포·관리해주는 오케스트레이션 도구다. |
| 2 | X | K8s의 핵심은 원하는 상태를 '선언'만 하면 K8s가 그 상태를 계속 자동으로 유지해준다는 점이다. |
| 3 | O | Control Plane(API Server, Scheduler, etcd 등)은 '두뇌', Worker Node는 Pod가 돌아가는 '일꾼'이다. |
| 4 | X | 이론적으로는 노드 1대여도 클러스터다. 우리가 쓰는 minikube도 기본적으로 노드 1대짜리 클러스터다. |
| 5 | X | minikube는 클러스터 전체를 VM 한 대 안에 압축해서 넣어둔 것으로, 노드 1대짜리 클러스터를 로컬에서 연습할 수 있게 해준다. |
| 6 | (예시) Docker는 컨테이너 하나를 만들고 실행하는 도구이고, Kubernetes는 그렇게 만들어진 컨테이너들을 여러 대의 서버에 걸쳐 관리해주는 도구다(대체 관계가 아니라 함께 쓰는 관계). | 핵심은 "역할이 다르며 함께 쓰인다"는 취지가 담기면 정답 처리 |
| 7 | 자가치유 | Pod가 죽으면 K8s가 자동으로 다시 띄워주는 것을 자가치유라고 하며, 7주차에 자세히 실습한다. |
| 8 | `kubectl get nodes` | 클러스터에 참여한 노드 목록과 각 노드의 STATUS·ROLES를 확인할 수 있다. |
