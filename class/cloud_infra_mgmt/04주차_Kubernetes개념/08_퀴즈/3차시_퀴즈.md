# 4주차 3차시 — Deployment·YAML 선언 퀴즈 (OX·단답형 8문항)

- 범위: 4주차 3차시(Deployment로 Pod 자동 관리하기, YAML로 선언하기)
- 형식: OX 5문항 + 단답형 3문항
- 용도: LMS 자동채점 퀴즈. 수업 중 함께 풀고 바로 정답·해설을 확인합니다.

---

## OX 문제 (1~5번)

**1.** Deployment의 핵심은 '지금 nginx Pod 2개를 만들어라'라는 명령이 아니라, '항상 nginx Pod가
2개 떠 있어야 한다'라는 선언이다. ( )

**2.** Deployment는 내부적으로 ReplicaSet을 만들어서 Pod 개수를 계속 감시한다. ( )

**3.** YAML 파일에서 `kind`는 replicas 개수처럼 '원하는 상태'를 적는 항목이다. ( )

**4.** YAML 파일에서는 들여쓰기(스페이스 칸 수)가 정확하지 않아도 실행에 아무 문제가 없다. ( )

**5.** Deployment로 관리되는 Pod 중 하나를 강제로 삭제해도, 잠시 후 다시 원래 개수(예: 2개)로
복구된다. ( )

## 단답형 문제 (6~8번)

**6.** Deployment YAML 파일을 구성하는 기본 4가지 항목을 순서대로 쓰세요.

**7.** `kubectl apply -f deployment.yaml`로 배포한 뒤, Pod가 만들어지는 과정을 상태가 바뀔 때마다
실시간으로 지켜볼 수 있게 해주는 명령어(옵션 포함)를 쓰세요.

**8.** Deployment가 관리하는 Pod를 삭제해도 다시 채워지는 이 현상을 부르는 이름을 쓰고, 이 원리를
자세히 다루는 주차를 쓰세요.

---

## 정답 및 해설

| 번호 | 정답 | 해설 |
|---|---|---|
| 1 | O | K8s의 핵심 철학은 '명령'이 아니라 '선언'이다 — 원하는 최종 상태만 말해주면 K8s가 그 상태를 유지한다. |
| 2 | O | Deployment는 ReplicaSet을 만들어 Pod 개수를 감시하고, 부족하면 새로 채운다. |
| 3 | X | `kind`는 무엇을 만들지(Deployment, Pod, Service 등)를 적는 항목이다. 원하는 상태는 `spec`에 적는다. |
| 4 | X | YAML에서 가장 중요한 것이 들여쓰기다. 스페이스 칸 수가 안 맞으면 오류가 난다. |
| 5 | O | ReplicaSet이 부족해진 개수를 즉시 감지해 새 Pod를 만들어 채운다(선언적 관리, 자가치유의 예시). |
| 6 | `apiVersion`, `kind`, `metadata`, `spec` | apiVersion(API 버전) → kind(무엇을 만들지) → metadata(이름표) → spec(원하는 상태) 순서다. |
| 7 | `kubectl get pods -w` | `-w`(watch) 옵션은 상태가 바뀔 때마다 새 줄로 계속 보여준다. `Ctrl+C`로 빠져나올 수 있다. |
| 8 | 자가치유(self-healing), 7주차 | Deployment의 선언적 관리가 실제로 작동하는 예시이며, 원리는 7주차에 자세히 다룬다. |
