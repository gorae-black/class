# 4주차 1차시 실습가이드
## Kubernetes, 왜 필요한가

## 개요

컨테이너 수가 많아지고 서버가 여러 대로 늘어나면, 사람이 손으로 컨테이너를 관리하는 데는 한계가
있습니다. **Kubernetes(K8s)**는 여러 대의 서버(노드)에 걸쳐 컨테이너를 자동으로 배포·관리해주는
오케스트레이션 도구입니다. 오늘은 이론 중심 시간으로, K8s 클러스터가 크게 **Control Plane(두뇌)**과
**Worker Node(일꾼)**로 나뉜다는 큰 그림을 잡고, 실습에서는 클러스터에 처음 접속해 이 구조를 눈으로
직접 확인합니다.

- 소요시간: 개념 설명 25분 + Killercoda 실습 15분 + VM 안내 5분 + 결과 제출 5분 (총 50분)
- 오늘 실습의 목표: 세부 명령어를 외우는 것이 아니라, `kubectl get nodes`와 `kubectl cluster-info`
  결과가 무엇을 보여주는지 눈으로 확인하는 것입니다. 실제 배포와 세부 문법은 다음 2·3차시부터
  본격적으로 다룹니다.

## Part A. Killercoda 실습

LMS > 4주차 > `05_Killercoda_링크`에 있는 1차시 링크로 접속한 뒤, 아래 순서대로 진행하세요.

> **⚠️ 참고: 이 실습 환경은 개인 VM(minikube)과 노드 구성이 다릅니다**
>
> 이 Killercoda 환경은 **Control Plane 1대 + Worker Node 1대, 총 2대**로 구성되어 있습니다. 반면
> 앞으로 여러분이 쓸 개인 VM의 minikube는 노드 **1대**가 Control Plane과 Worker 역할을 동시에
> 맡습니다(이론적으로는 노드 1대여도 클러스터입니다). 노드 수는 다르지만, `kubectl get nodes`로
> 클러스터 구성을 확인하는 방법과 원리는 동일합니다.
>
> 이 세션에는 **60분 제한**이 있습니다. 오늘 실습은 짧게 끝나므로 문제 없지만, 중간에 끊기면 LMS
> 링크로 다시 접속해 이어서 진행하면 됩니다.

### Step 1. 클러스터 노드 확인하기

`kubectl get nodes`로 이 클러스터에 어떤 노드들이 있는지 확인합니다.

```
kubectl get nodes
```

**실행 결과 예시**

```
NAME           STATUS   ROLES           AGE   VERSION
controlplane   Ready    control-plane   5m    v1.30.1
node01         Ready    <none>          5m    v1.30.1
```

STATUS가 둘 다 `Ready`이면 두 노드 모두 정상적으로 클러스터에 참여해 있다는 뜻입니다. ROLES 칸의
`control-plane`은 `controlplane` 노드가 '두뇌' 역할을 맡고 있다는 표시이고, `node01`의 `<none>`은
이 노드가 '일꾼(Worker)' 역할이라는 뜻입니다.

### Step 2. Control Plane 정보 확인하기

`kubectl cluster-info`로 Control Plane이 어느 주소에서 실행되고 있는지 확인합니다.

```
kubectl cluster-info
```

**실행 결과 예시**

```
Kubernetes control plane is running at https://172.30.1.2:6443
CoreDNS is running at https://172.30.1.2:6443/api/v1/namespaces/kube-system/services/kube-dns:dns/proxy
```

(IP 주소는 실습 환경마다 다르게 나올 수 있습니다.) 이 주소가 바로 방금 `kubectl get nodes`에서 본
그 노드 안에서, Control Plane이 실제로 요청에 응답하고 있는 곳입니다.

여기까지가 오늘의 Killercoda 실습입니다. 수고하셨습니다!

## Part B. 개인 VM 실습

개인 로컬 VM(cloud-lab)에는 이미 minikube가 설치되어 있습니다(0주차에 배포받은 VM 이미지에 미리
설치되어 있으므로 별도 설치 불필요).

1. VM에 접속한 뒤 아래 명령으로 로컬 1노드 클러스터를 켭니다.

   ```
   minikube start
   ```

   처음 실행할 때는 1~2분 정도 걸릴 수 있습니다.

2. 완료되면 노드가 `Ready` 상태인지 확인합니다.

   ```
   kubectl get nodes
   ```

   Killercoda에서는 노드가 2개(`controlplane`, `node01`) 나왔지만, minikube는 노드가 **1대**뿐이므로
   결과에 노드가 하나만 나오는 것이 정상입니다. 그 노드 1대가 Control Plane과 Worker 역할을 모두
   겸하고 있습니다.

다음 차시부터 이 클러스터를 계속 이어서 사용하니, 오늘 미리 한 번 켜서 정상 동작하는지 확인해두면
좋습니다.
