# 10주차 1차시 실습가이드
## 원격 State와 Terraform Cloud

## 개요

지금까지 Terraform State 파일은 항상 VM 로컬 디스크에만 있었습니다. 혼자 쓸 땐 문제가 없어
보이지만, 이 방식은 협업(State 충돌), 보안(민감정보 평문 노출), 실행 환경(VM이 꺼지면 아무도
apply 못 함) 세 가지 문제를 가지고 있습니다. 오늘은 이 문제를 해결해주는 HashiCorp의 공식 서비스
**Terraform Cloud**를 개념으로 배웁니다 — State를 원격 저장소에 안전하게 보관하고, `plan`/`apply`
연산 자체도 내 VM이 아니라 Terraform Cloud의 서버에서 실행(원격 실행, Remote Execution)해주는
서비스입니다.

- 소요시간: 개념 설명 25분 + Killercoda 시연 감상 15분 + VM 안내 5분 + 결과 제출 5분 (총 50분)
- 오늘은 아직 Terraform Cloud 계정을 만들지 않습니다. 계정 가입은 다음 2차시에 진행합니다.

---

## 개념 시연 관찰 포인트 (수업 중 교수자 화면 공유)

오늘 Killercoda 시간은 직접 조작하는 실습이 아니라, **완성된 그림을 먼저 보는 시간**입니다.
교수자가 미리 준비한 GitHub 템플릿을 기반으로 Terraform Cloud 파이프라인이 실제로 동작하는 과정을
화면 공유로 함께 관찰합니다.

관찰 포인트:

- GitHub 저장소에 코드를 push하면, Terraform Cloud의 **Runs** 탭에 자동으로 plan이 잡히는 흐름
- 이 파이프라인 전체를 다음 2·3차시에 걸쳐 여러분이 직접 처음부터 만들어보게 된다는 점

오늘은 "이런 게 가능하구나"를 눈으로 확인하는 시간이며, 별도로 따라 타이핑할 필요는 없습니다.

## VM 실습

오늘은 개념 위주 차시라 **VM에서 진행할 실습은 없습니다.** Terraform Cloud 계정도 아직 만들지
않습니다.

다음 2차시 도입부에서 계정·조직·워크스페이스 생성을 스크린샷과 함께 단계별로 안내할 예정이니
미리 걱정하지 않아도 됩니다. 다만 원한다면, 다음 시간 가입에 사용할 이메일 주소를 하나 미리
정해두는 것도 좋습니다(선택 사항).

**오늘 꼭 기억해둘 함정**: 원격 실행은 Terraform Cloud의 **서버**에서 이뤄지기 때문에 내 VM의
로컬 자원(예: Docker)에는 접근할 수 없습니다. 그래서 9주차에 썼던 `docker` Provider 예제를
Terraform Cloud에서 그대로 원격 실행하면 "Cannot connect to the Docker daemon" 오류가 납니다.
다음 3차시 실습에서는 로컬 인프라에 의존하지 않는 `random_pet` 리소스로 원격 실행의 원리만
확인할 예정입니다.
