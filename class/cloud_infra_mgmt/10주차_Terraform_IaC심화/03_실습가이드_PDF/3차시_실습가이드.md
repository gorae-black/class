# 10주차 3차시 실습가이드
## GitHub 연동과 원격 실행 확인

## 개요

지난 시간에 워크스페이스를 만들고 CLI 연동까지 마쳤습니다. 오늘은 실제로 GitHub과 연동하고,
처음으로 Terraform Cloud에서 원격 실행(`apply`)까지 성공시켜봅니다. 단, 9주차에 썼던
`docker_container` 예제를 그대로 쓰면 원격 실행 서버가 학생 VM의 Docker 데몬에 접근할 방법이
없어 "Cannot connect to the Docker daemon" 오류가 나므로, 오늘은 로컬 인프라에 전혀 의존하지 않는
`random` Provider의 `random_pet` 리소스를 사용합니다.

- 소요시간: 개념 설명 25분 + Killercoda 시연 감상 15분 + VM 안내 5분 + 결과 제출 5분 (총 50분)
- 이번 차시는 10주차의 마지막이자 9~10주차 Terraform IaC 단원 전체의 마무리입니다.

## 개념 시연 관찰 포인트 (수업 중 교수자 화면 공유)

오늘 Killercoda 시간은 교수자가 미리 GitHub과 연동해 둔 워크스페이스에서 실제 **Runs** 이력을
함께 살펴보는 시간입니다.

관찰 포인트:

- 누가, 언제, 어떤 코드 변경으로 실행했는지가 로그로 남아있는 모습
- '원격 실행'이라는 개념이 실제 로그를 보면 더 체감된다는 점

## VM 실습

개인 VM에서 2차시에 만든 워크스페이스에 이어서 진행합니다.

### Step 1. main.tf 작성 — random_pet 예제

```hcl
resource "random_pet" "lab" {
  length = 2
}
output "pet_name" {
  value = random_pet.lab.id
}
```

`random_pet`은 무작위 형용사+동물 이름을 만들어주는 리소스입니다. `length = 2`는 단어를 2개
조합한다는 뜻입니다.

### Step 2. 초기화 및 원격 실행

```
terraform init
```

2차시에 만든 `cloud` 블록의 워크스페이스에 연결됩니다.

```
terraform apply
```

이 순간 실제 plan/apply 연산은 **Terraform Cloud 서버**에서 실행됩니다.

```
terraform output
```

결과값(`pet_name`)을 확인합니다. 예: `pet_name = "grand-quail"`

### Step 3. Runs 탭에서 실행 이력 확인

`app.terraform.io`에 접속해 워크스페이스의 **Runs** 탭을 열어보면, 방금 실행한 기록이 그대로
남아있는 것을 확인할 수 있습니다.
