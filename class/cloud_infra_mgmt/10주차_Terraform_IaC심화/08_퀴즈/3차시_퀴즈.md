# 10주차 3차시 — GitHub 연동과 원격 실행 확인 퀴즈 (OX·단답형 10문항)

- 범위: 10주차 3차시(random_pet, 하이브리드 GitOps, 원격 apply, Runs 탭)
- 형식: OX 6문항 + 단답형 4문항
- 용도: LMS 자동채점 퀴즈. 수업 중 함께 풀고 바로 정답·해설을 확인합니다.

---

## OX 문제 (1~6번)

**1.** 9주차에 썼던 `docker_container` 예제를 Terraform Cloud에서 원격 실행하면 문제 없이
정상적으로 동작한다. ( )

**2.** `random_pet` 리소스는 로컬 인프라(Docker 등)에 전혀 의존하지 않는다. ( )

**3.** GitOps란 코드 변경이 Git을 매개로 자동으로 인프라에 반영되는 방식을 말한다. ( )

**4.** `terraform apply`를 실행하면, 실제 plan/apply 연산은 학생의 개인 VM에서 처리된다. ( )

**5.** 10주차 실습 결과는 9주차와 별도로 제출해야 한다. ( )

**6.** 다음 11주차부터는 Jenkins CI/CD 단원이 시작된다. ( )

## 단답형 문제 (7~10번)

**7.** `random_pet` 리소스에서 `length = 2`로 설정하면 이름이 몇 개의 단어로 조합되나요?

**8.** `terraform apply` 이후 `pet_name` 같은 결과값을 확인할 때 사용하는 명령어는 무엇인가요?

**9.** GitHub 저장소에 코드를 push하면, Terraform Cloud가 자동으로 실행하는 것은 무엇인가요?

**10.** 원격 실행 기록(누가 언제 무엇을 실행했는지)을 확인할 수 있는 Terraform Cloud UI의 탭
이름은 무엇인가요?

---

## 정답 및 해설

| 번호 | 정답 | 해설 |
|---|---|---|
| 1 | X | 원격 실행 서버는 학생 VM의 Docker 데몬에 접근할 방법이 없어 "Cannot connect to the Docker daemon" 오류가 난다. |
| 2 | O | `random_pet`은 실제 인프라를 만들지 않고 무작위 이름만 생성하므로 로컬 자원에 의존하지 않아, 원격 실행 검증에 적합하다. |
| 3 | O | 코드 변경이 Git(push)을 매개로 자동으로 인프라에 반영되는 방식을 GitOps라 부른다. |
| 4 | X | 원격 실행은 학생 VM이 아니라 Terraform Cloud의 **서버**에서 이뤄진다. |
| 5 | X | 3차시가 10주차 마지막이므로, 9주차(로컬 Terraform)와 10주차(Terraform Cloud) 실습을 함께 정리해서 제출한다. |
| 6 | O | 다음 주부터는 Jenkins를 이용한 CI/CD 단원(11~13주차)이 시작된다. |
| 7 | 2개 | `length = 2`는 형용사+동물 이름 등 단어 2개를 조합한다는 뜻이다. |
| 8 | `terraform output` | 실행 후 저장된 output 값(`pet_name`)을 확인할 때 사용한다. |
| 9 | plan(자동 plan 실행) | 워크스페이스가 GitHub 저장소와 연결(VCS 연동)되어 있으면, push가 감지될 때마다 자동으로 plan이 실행된다. |
| 10 | Runs | Runs 탭에서 누가, 언제, 어떤 코드 변경으로 실행했는지 이력을 확인할 수 있다. |
