# 13주차 1차시 실습가이드

## 개요

13~14주차는 지금까지 배운 Docker(1~3주차)·Kubernetes(4~7주차)·Terraform(9~10주차)·Jenkins(11~12주차)를
하나로 합쳐서, AI 미니 챗봇 웹 앱을 Git → Jenkins → Docker Hub → K8s로 완전 자동 배포하는 파이프라인을
만드는 대통합 실습입니다. 13~14주차는 **100% 학생 개인 VM 안에서, 시간 제약 없이** 진행합니다 —
지금까지와 달리 Killercoda(60분 제한)는 사용하지 않습니다. 여러 도구가 복잡하게 연결되는 만큼 문제가
생기면 디버깅에 시간이 걸릴 수 있어, 시간 압박 없이 진행하기 위함입니다.

오늘 1차시는 실제 구축에 들어가기 전, 전체 아키텍처를 이해하고 다음 실습을 준비하는 시간입니다.

- 소요시간: 50분 (개념 설명 20분 + VM 실습 25분 + 결과 정리 5분)

## VM 실습

### 1. 완성할 파이프라인 전체 그림 이해하기

오늘부터 완성해나갈 파이프라인은 다음 4단계입니다.

1. 학생 PC 에디터에서 소스를 수정하고 `git push origin main`을 실행한다.
2. 로컬 VM의 Jenkins가 Poll SCM(매 1분)으로 이 변경을 감지한다.
3. Jenkins가 Docker 이미지를 빌드하고 Docker Hub에 Push한다.
4. Jenkins가 minikube의 Deployment 이미지를 새 버전으로 교체한다(Rolling Update).

각 도구의 역할을 지금까지 배운 내용과 연결하면 다음과 같습니다.

| 도구 | 배운 주차 | 오늘 파이프라인에서의 역할 |
|---|---|---|
| Git/GitHub | 9~10주차 | 소스 코드의 버전을 기록하고 변경을 공유 |
| Docker | 1~3주차 | 챗봇 앱을 이미지로 포장해서 어디서든 동일하게 실행 |
| Jenkins | 11~12주차 | 코드 변경을 감지해서 빌드·배포를 자동으로 실행 |
| Kubernetes | 4~7주차 | 챗봇 컨테이너를 운영하고, 새 버전으로 무중단 교체 |

### 2. 미니 챗봇 뼈대 코드 구조 파악하기

오늘 배포할 대상은 Flask로 만든 간단한 웹 앱으로, 사용자가 메시지를 보내면 규칙 기반으로 응답하는
미니 챗봇입니다. 이 실습의 핵심은 챗봇 자체의 성능이 아니라, 이 앱이 **자동으로 빌드·배포·업데이트되는
전체 과정**입니다.

`04_템플릿코드`에 준비된 챗봇 뼈대 코드를 VM에 내려받아 다음 세 파일의 구조를 한 번씩 읽어보세요.

- `app.py` — 어떻게 응답을 만드는지
- `Dockerfile` — 어떻게 이미지를 빌드하는지
- `deployment.yaml` — K8s에 어떻게 배포하는지

### 3. 파이프라인 흐름도 직접 그려보기

종이나 그림 도구로 위에서 배운 4단계 파이프라인(학생 PC → GitHub → Jenkins → Minikube)을 스스로
다시 그려보세요. 각 단계에서 어떤 명령어가 실행될지도 미리 메모해두세요. 다음 2차시에 이 흐름도를
실제 코드로 작성합니다.
