# 13주차 2차시 — 파이프라인 구축 퀴즈 (OX·단답형 10문항)

- 범위: 13주차 2차시(파이프라인 구축)
- 형식: OX 6문항 + 단답형 4문항
- 용도: LMS 자동채점 퀴즈. 수업 중 함께 풀고 바로 정답·해설을 확인합니다.

---

## OX 문제 (1~6번)

**1.** Jenkinsfile의 Deploy 단계에서 kubectl 명령을 바로 실행하면 minikube에 정상적으로 접속된다. ( )

**2.** Jenkins와 minikube는 각각 별도의 Docker 컨테이너로 떠 있다. ( )

**3.** `docker exec` 방식은 minikube 컨테이너 안에 이미 들어있는 kubectl과 인증 정보(admin.conf)를
그대로 활용하는 방법이다. ( )

**4.** `dockerhub-cred` 크리덴셜은 Deploy 단계까지 다 만든 뒤 마지막에 등록해도 된다. ( )

**5.** `withCredentials`를 쓰면 Jenkinsfile 코드 안에 Docker Hub 비밀번호가 평문 그대로 노출된다. ( )

**6.** `rollout status` 명령은 Rolling Update가 끝날 때까지 기다리는 명령이다. ( )

## 단답형 문제 (7~10번)

**7.** Jenkinsfile Deploy 단계에서 minikube 컨테이너 내부의 kubectl을 실행하기 위해 사용하는
Docker 명령어는 무엇인가요?

**8.** Build 단계에서 이미지에 버전 태그를 붙이기 위해 사용하는 Jenkins 내장 변수는 무엇인가요?

**9.** 오늘 완성한 Jenkinsfile의 4단계를 순서대로 쓰세요.

**10.** Jenkins가 minikube에 직접 네트워크로 접속하지 못하는 이유를 한 문장으로 쓰세요.

---

## 정답 및 해설

| 번호 | 정답 | 해설 |
|---|---|---|
| 1 | X | Jenkins와 minikube가 각각 별도 Docker 컨테이너로 떠 있어, 별도 Docker 네트워크와 IP 충돌 문제로 접속이 안 된다(검증된 결과). |
| 2 | O | Jenkins도, minikube도 각각 별도의 Docker 컨테이너로 떠 있다. |
| 3 | O | minikube 컨테이너 내부에는 이미 kubectl과 클러스터 인증 정보(admin.conf)가 전부 들어있어, `docker exec`로 이를 그대로 활용한다. |
| 4 | X | Deploy 단계에서 인증 오류로 막히지 않도록, 실습을 시작하기 전에 먼저 `dockerhub-cred`를 등록해야 한다. |
| 5 | X | `withCredentials`를 쓰면 Jenkinsfile 코드 안에는 비밀번호가 그대로 적히지 않고, Jenkins가 안전하게 저장해둔 값을 실행 시점에만 주입한다. |
| 6 | O | `rollout status`는 이 교체(Rolling Update)가 끝날 때까지 기다리는 명령이다. |
| 7 | `docker exec` | `docker exec minikube ...` 형태로 minikube 컨테이너 안의 kubectl을 실행한다. |
| 8 | `${BUILD_NUMBER}` | `${BUILD_NUMBER}`로 이미지에 버전 태그를 붙인다. |
| 9 | Checkout → Build → Push → Deploy | 네 단계로 Git부터 K8s까지 이어지는 파이프라인을 완성한다. |
| 10 | Jenkins와 minikube가 각각 별도의 Docker 컨테이너로 떠 있어, 별도 Docker 네트워크와 IP 충돌 문제 때문에 네트워크상 접속이 안 된다. | 그래서 11주차에 마운트했던 `docker.sock`을 이용해 `docker exec`로 우회한다. |
