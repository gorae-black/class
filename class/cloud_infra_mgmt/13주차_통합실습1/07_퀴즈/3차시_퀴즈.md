# 13주차 3차시 — End-to-End 배포 테스트와 트러블슈팅 퀴즈 (OX·단답형 10문항)

- 범위: 13주차 3차시(End-to-End 배포 테스트와 트러블슈팅)
- 형식: OX 6문항 + 단답형 4문항
- 용도: LMS 자동채점 퀴즈. 수업 중 함께 풀고 바로 정답·해설을 확인합니다.

---

## OX 문제 (1~6번)

**1.** 오늘 실습에서는 Build Now 버튼을 눌러 파이프라인을 수동으로 실행해야 한다. ( )

**2.** Poll SCM 설정 주기는 매 1분(`* * * * *`)이다. ( )

**3.** 파이프라인이 실패했을 때 가장 먼저 확인해야 할 것은 Console Output의 오류 메시지다. ( )

**4.** Push 단계에서 오류가 나는 가장 흔한 원인은 minikube가 꺼져있는 경우이다. ( )

**5.** 오늘 실습 결과 확인은 `curl $(minikube service chatbot --url)` 명령으로 챗봇 응답을
확인하는 방식이다. ( )

**6.** 13주차 3차시에는 1~3차시 중 아무 한 차시만 골라서 제출하면 된다. ( )

## 단답형 문제 (7~10번)

**7.** 오늘 검증해야 하는 최종 목표를 한 문장으로 쓰세요.

**8.** Deploy 단계에서 자주 발생하는 문제 두 가지를 쓰세요.

**9.** 파이프라인이 실패했을 때의 진단 순서 3단계를 순서대로 쓰세요.

**10.** 다음 14주차에서 다룰 주제 두 가지를 쓰세요.

---

## 정답 및 해설

| 번호 | 정답 | 해설 |
|---|---|---|
| 1 | X | 오늘은 사람이 버튼을 누르지 않고, 코드 수정 → `git push`만으로 전체가 자동으로 돌아가는지 확인하는 End-to-End 테스트다. |
| 2 | O | Poll SCM 설정(`* * * * *`)이 제대로 저장돼야 push 후 자동으로 빌드가 트리거된다. |
| 3 | O | 막혔을 때는 Jenkins Job의 Console Output에서 빨간 글씨(오류 메시지)를 먼저 읽는다. |
| 4 | X | Push 단계 오류는 `dockerhub-cred`를 등록하지 않았거나 Docker Hub 아이디를 잘못 입력한 경우가 흔하다. minikube가 꺼져있는 것은 Deploy 단계에서 흔한 원인이다. |
| 5 | O | 빌드가 성공하면 `curl $(minikube service chatbot --url)`로 실제 응답이 바뀐 것을 확인한다. |
| 6 | X | 13주차 3차시는 마지막 시간으로, 1차시(아키텍처 설계)·2차시(구축)·3차시(오늘, E2E 테스트) 실습을 종합해서 제출해야 한다. |
| 7 | `app.py`의 챗봇 응답 문구를 수정하고 `git push`만으로, 실제 챗봇의 응답이 바뀌는 것을 확인하는 것 | 사람이 버튼을 누르지 않고 전체가 자동으로 돌아가는지 확인하는 것이 오늘의 최종 목표다. |
| 8 | Deployment나 컨테이너 이름이 실제 YAML과 다름, minikube가 꺼져있음 | Stage별 자주 발생하는 문제 표에 정리된 Deploy 단계의 흔한 원인이다. |
| 9 | ① Console Output에서 오류 메시지 확인 → ② Stage View 색깔로 어느 stage에서 멈췄는지 확인 → ③ 오류 메시지 검색 또는 같은 명령을 손으로 직접 실행해 재현 | 이 진단 과정 자체가 실무에서 개발자·엔지니어가 매일 하는 일이다. |
| 10 | HPA(오토스케일링), 자가치유 | 14주차에서는 대규모 트래픽을 흘려보내 K8s가 스스로 Pod를 늘리고, 장애가 나도 스스로 복구하는 모습을 관찰한다. |
