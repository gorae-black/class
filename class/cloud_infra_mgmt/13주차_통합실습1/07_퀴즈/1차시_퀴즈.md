# 13주차 1차시 — 파이프라인 아키텍처 설계 퀴즈 (OX·단답형 10문항)

- 범위: 13주차 1차시(파이프라인 아키텍처 설계)
- 형식: OX 6문항 + 단답형 4문항
- 용도: LMS 자동채점 퀴즈. 수업 중 함께 풀고 바로 정답·해설을 확인합니다.

---

## OX 문제 (1~6번)

**1.** 13~14주차는 Killercoda의 60분 시간 제한 안에서 진행된다. ( )

**2.** 오늘 완성해나갈 파이프라인은 학생 PC에서 `git push origin main`을 실행하는 것으로 시작된다. ( )

**3.** Jenkins는 Poll SCM으로 매 1분마다 소스 코드 변경을 감지한다. ( )

**4.** 이 파이프라인에서 소스 코드의 버전을 기록하고 변경을 공유하는 역할은 Kubernetes가 맡는다. ( )

**5.** Rolling Update는 기존 Pod를 한꺼번에 삭제하고 새 Pod로 교체하는 방식이다. ( )

**6.** 오늘 배포할 미니 챗봇은 Flask로 만든 규칙 기반 응답 웹 앱이다. ( )

## 단답형 문제 (7~10번)

**7.** 오늘 배운 파이프라인의 4단계를 순서대로 쓰세요.

**8.** Jenkins가 Docker Hub에 이미지를 올린 뒤, minikube에서 실행 중인 이미지를 새 버전으로
순차적으로 교체하는 방식을 무엇이라 부르나요?

**9.** Git/GitHub, Docker, Jenkins, Kubernetes 중 "챗봇 앱을 이미지로 포장해서 어디서든 동일하게
실행되게 하는" 역할을 맡는 도구는 무엇인가요?

**10.** 오늘 실습 결과물로 제출해야 하는 것 두 가지를 쓰세요.

## 정답 및 해설

| 번호 | 정답 | 해설 |
|---|---|---|
| 1 | X | 13~14주차는 Killercoda 없이, 100% 학생 개인 VM 안에서 시간 제약 없이 진행한다. |
| 2 | O | 학생 PC 에디터에서 소스를 수정하고 `git push origin main`을 실행하는 것이 파이프라인의 시작이다. |
| 3 | O | Jenkins는 12주차에 배운 Poll SCM(매 1분)으로 변경을 감지한다. |
| 4 | X | 소스 코드 버전 기록·공유는 Git/GitHub의 역할이다. Kubernetes는 컨테이너를 운영하고 새 버전으로 무중단 교체하는 역할을 맡는다. |
| 5 | X | Rolling Update는 기존 Pod를 한꺼번에 지우지 않고 하나씩 순차적으로 교체하는 방식이라, 교체 도중에도 서비스가 완전히 끊기지 않는다. |
| 6 | O | 미니 챗봇은 Flask로 만든 간단한 웹 앱으로, 규칙 기반으로 응답한다. |
| 7 | 학생 PC → GitHub → Jenkins → Minikube | 학생 PC에서 push하면 Jenkins가 감지해 빌드·Push하고, minikube의 Deployment 이미지를 교체한다. |
| 8 | Rolling Update | K8s Deployment가 새 이미지로 Pod를 하나씩 순차적으로 교체하는 방식이다. |
| 9 | Docker | Docker는 챗봇 앱을 이미지로 포장해서 어디서든 동일하게 실행되게 한다. |
| 10 | 직접 그린 파이프라인 흐름도(사진/스캔) + 챗봇 뼈대 코드 구조를 훑어본 소감(3줄 이상) | 오늘은 구축이 아니라 예습·이해 성격의 실습이라, 흐름도와 소감이 제출물이다. |
