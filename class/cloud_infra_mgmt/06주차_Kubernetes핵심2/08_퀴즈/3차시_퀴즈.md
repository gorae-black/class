# 6주차 3차시 — MySQL로 데이터 영속성 검증하기 퀴즈 (OX·단답형 8문항)

- 범위: 6주차 3차시(MySQL로 데이터 영속성 검증하기)
- 형식: OX 5문항 + 단답형 3문항
- 용도: LMS 자동채점 퀴즈. 수업 중 함께 풀고 바로 정답·해설을 확인합니다.

---

## OX 문제 (1~5번)

**1.** MySQL 데이터를 영속적으로 보존하려면, Pod YAML의 `volumes`에 PVC 이름을 지정하고
`volumeMounts`로 컨테이너 안 경로에 연결해야 한다. ( )

**2.** 오늘 실습에서 MySQL이 데이터를 저장하는 경로는 `/etc/mysql`이다. ( )

**3.** Deployment로 배포한 MySQL Pod를 강제로 삭제하면, 자동으로 새 Pod가 만들어진다. ( )

**4.** MySQL Pod가 삭제된 후 새 Pod는 곧바로(수 초 이내) Running 상태가 되므로 기다릴 필요가
없다. ( )

**5.** 만약 PVC 없이 그냥 MySQL을 배포했다면, Pod가 삭제되고 새로 생기는 순간 데이터가 전부
사라졌을 것이다. ( )

## 단답형 문제 (6~8번)

**6.** 실무에서는 `MYSQL_ROOT_PASSWORD` 같은 비밀번호를 YAML에 평문으로 쓰는 대신, 어떤 K8s
오브젝트를 사용해서 관리하는 것이 표준인가요?

**7.** hostPath 방식이 실무에서는 잘 사용되지 않는 이유를 한 문장으로 쓰세요.

**8.** 영속성 검증 절차에서, Pod 삭제 후 새 Pod가 완전히 Running 상태가 되기까지 대략 얼마나
걸리나요?

---

## 정답 및 해설

| 번호 | 정답 | 해설 |
|---|---|---|
| 1 | O | Pod YAML의 `volumes`에 PVC 이름을 지정하고, 컨테이너의 `volumeMounts`로 그 볼륨을 컨테이너 안 특정 경로에 연결해야 실제 저장공간(PV)과 이어진다. |
| 2 | X | 오늘 실습에서 MySQL이 데이터를 저장하는 경로는 `/var/lib/mysql`이다. |
| 3 | O | Deployment는 원하는 개수(오늘은 1개)의 Pod를 항상 유지하려 하기 때문에, Pod가 삭제되면 자동으로 새 Pod를 만들어준다. |
| 4 | X | 새 컨테이너를 만들고 MySQL 프로세스가 초기화되는 데 **10~20초 정도** 걸린다. MySQL은 시작 시 여러 초기화 작업을 하기 때문에 nginx 같은 가벼운 이미지보다 시간이 더 걸린다. |
| 5 | O | PVC 없이 배포했다면 Pod와 함께 데이터도 사라졌을 것이다. 오늘은 PVC 덕분에 데이터가 Pod의 생명주기와 무관하게 살아남는 것을 확인했다. |
| 6 | Secret | 비밀번호를 YAML에 평문으로 쓰는 대신 1차시에 배운 Secret에서 불러오는 방식이 실무 표준이다. 오늘 실습에서는 간단하게 환경변수로 직접 지정했다. |
| 7 | (예시) hostPath는 노드 하나에 데이터가 묶여있어서, 그 노드가 사라지면 데이터도 함께 사라지기 때문 | 핵심은 "노드 종속성" — 채점 시 이 취지가 담기면 정답 처리. 실무에서는 클라우드 스토리지나 네트워크 스토리지로 노드와 무관하게 데이터를 보존한다. |
| 8 | 10~20초 | MySQL은 시작 시 내부적으로 여러 초기화 작업을 하기 때문에 이 정도 시간이 걸린다. |
