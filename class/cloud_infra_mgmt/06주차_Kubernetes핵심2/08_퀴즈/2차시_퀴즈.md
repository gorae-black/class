# 6주차 2차시 — PV와 PVC로 데이터 지키기 퀴즈 (OX·단답형 8문항)

- 범위: 6주차 2차시(PV와 PVC로 데이터 지키기)
- 형식: OX 5문항 + 단답형 3문항
- 용도: LMS 자동채점 퀴즈. 수업 중 함께 풀고 바로 정답·해설을 확인합니다.

---

## OX 문제 (1~5번)

**1.** Pod는 K8s만의 특별한 존재라서, 컨테이너와 달리 삭제해도 그 안의 데이터가 자동으로 보존된다.
( )

**2.** PV(PersistentVolume)는 실제로 존재하는 저장공간 그 자체이고, PVC(PersistentVolumeClaim)는
그 저장공간이 필요하다고 요청하는 요청서이다. ( )

**3.** Pod는 PVC를 통해 PV에 연결되므로, 실제 저장공간이 어디에 있는지 직접 알 필요가 없다. ( )

**4.** hostPath 방식의 PV는 노드(VM)의 특정 디렉토리를 그대로 저장공간으로 사용한다. ( )

**5.** PVC의 STATUS가 계속 `Pending`으로 남아있다면, 이는 PV와 PVC가 이미 정상적으로 연결되었다는
뜻이다. ( )

## 단답형 문제 (6~8번)

**6.** PV와 PVC가 정상적으로 연결되었을 때, `kubectl get pv`와 `kubectl get pvc`의 STATUS 칸에
나타나는 값은 무엇인가요?

**7.** 오늘 실습에서 사용한, 노드의 특정 디렉토리를 PV로 그대로 사용하는 방식의 이름을 쓰세요.

**8.** 클라우드 환경에서는 hostPath 대신 실제 클라우드 스토리지를 PV로 연결하기도 합니다. 그 예시를
한 가지 쓰세요.

---

## 정답 및 해설

| 번호 | 정답 | 해설 |
|---|---|---|
| 1 | X | Pod도 결국 컨테이너를 감싸고 있는 것이라서, 컨테이너와 마찬가지로 삭제하면 데이터도 함께 사라진다. 이 문제를 해결하기 위해 PV/PVC를 사용한다. |
| 2 | O | PV는 실제 저장공간, PVC는 그 저장공간을 향한 요청서다. |
| 3 | O | Pod는 PVC에 "이런 조건의 저장공간을 달라"고 요청만 하면, PVC가 알아서 적절한 PV와 연결(Bound)해준다. |
| 4 | O | hostPath는 VM(노드)의 특정 디렉토리를 PV로 그대로 사용하는 방식으로, 2주차에 배운 Bind Mount와 원리가 비슷하다. |
| 5 | X | `Pending`은 PV와 PVC가 아직 연결되지 않은 상태다. 정상적으로 연결되면 STATUS는 `Bound`로 나온다. Pending이 계속되면 PV와 PVC의 용량·접근 모드가 서로 맞지 않는 경우가 많다. |
| 6 | Bound | PV와 PVC의 조건(용량, 접근 모드)이 맞아 정상적으로 연결되면 STATUS가 Bound로 표시된다. |
| 7 | hostPath | 노드의 특정 디렉토리를 PV로 그대로 사용하는 방식으로, 오늘 pv.yaml에서 `hostPath.path`로 지정했다. |
| 8 | (예시) AWS EBS, GCP Persistent Disk | 클라우드 환경에서는 이런 실제 클라우드 스토리지를 PV로 연결하는 방식도 많이 쓰인다. |
